title: The Toolchain for Diagnosing Production Problems
---

#### ① Sentry, automated

On every release, CI uploads that build's source maps under the release version and archives them — privately, never deployed publicly, so the source cannot be reconstructed from the map files. When the front-end SDK reports an error it carries the current release version, and Sentry matches it against the right map file and translates the minified stack into readable filenames and line numbers. No human step anywhere.

The one requirement is uploading the right maps under the right release. If the release number does not match, or the upload was skipped, the translation fails and you are left staring at minified positions.

#### ② git bisect — automated binary search

When working out which commit introduced a bug, do not walk the commits one by one. Mark a version that is known bad and one that is known good, verify only the midpoint each time, and you find the commit in roughly `log2(n)` steps instead of `n`.

```
git bisect start
git bisect bad HEAD
git bisect good v1.2.0
git bisect run npm test   # supply a script that decides automatically; no manual step at all
```

This assumes you have a fast way to decide whether a build is broken — a test case that reproduces it locally. Otherwise each check means a full deploy and the advantage evaporates.

#### ③ Feature flags — decoupling "shipped" from "live"

Being able to switch something off in seconds comes from separating "is this code deployed" from "is this feature shown to users". The code can already be in production while a remote config decides whether it takes effect. When something breaks you change the config — no redeploy, and it takes seconds. Rolling back code means a full build and deploy, which takes minutes.

How to do a percentage rollout: hash the user ID into the range 0–99, and treat `bucket < percentage` as in. The hash is deterministic, so a given user's bucket never changes, which means widening the rollout — 1% to 10%, say — keeps the original users inside the new range instead of reshuffling everyone.
