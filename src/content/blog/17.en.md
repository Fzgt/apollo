## Generics

A generic is a parameterised type. Just as a function takes arguments, generics let you give a type parameters, which makes it reusable and flexible.

```ts
function identity<T>(value: T): T {
  return value;
}
```

### Generic constraints

Sometimes you want to narrow what a generic accepts. That is what `extends` is for:

```ts
function getLength<T extends { length: number }>(arg: T): number {
  return arg.length;
}

getLength([1, 2, 3]); // ✅
getLength("hello");   // ✅
getLength(42);        // ❌ number has no length

```

## `type`

The `type` keyword gives a type an alias, and lets you combine and operate on types.

```ts
type ID = string | number;

let userId: ID;
userId = "abc";
userId = 123;

// with generics
type ApiResponse<T> = {
  data: T;
  error?: string;
};

const res1: ApiResponse<string> = { data: "ok" };
const res2: ApiResponse<number[]> = { data: [1, 2, 3] };

```

### `type` vs `interface`

- `interface` suits object shapes better and can be extended (`extends`, declaration merging).
- `type` is more flexible: unions, intersections, conditional types.

```ts
// extending an interface
interface A { x: number }
interface B extends A { y: string }

// operating on types
type C = { x: number } & { y: string };
```

## Five groups of mapped types

Mapped types build a new type in bulk from an existing one. They are mostly used to operate on an object's properties.

### 1. Per-property: Partial, Required, Readonly

#### `Partial<T>` — make every property optional

```ts
type User = { id: number; name: string };

type UserPartial = Partial<User>;
// same as { id?: number; name?: string }
```

#### `Required<T>` — make every property required

```ts
type User = { id?: number; name?: string };

type UserRequired = Required<User>;
// same as { id: number; name: string }
```

#### `Readonly<T>` — make every property read-only

```ts
type User = { id: number; name: string };

type UserReadonly = Readonly<User>;
// same as { readonly id: number; readonly name: string }
```

### 2. Selecting and filtering: Pick, Omit

#### `Pick<T, K>` — build a new type from selected properties

```ts
type User = { id: number; name: string; age: number };

type UserBasic = Pick<User, "id" | "name">;
// { id: number; name: string }
```

#### `Omit<T, K>` — drop properties from T

```ts
type User = { id: number; name: string; age: number };

type UserWithoutAge = Omit<User, "age">;
// { id: number; name: string }
```

### 3. Set operations: Exclude, Extract, NonNullable

#### `Exclude<T, U>` — remove U from the union T

```ts
type A = "a" | "b" | "c";
type B = Exclude<A, "a">;
// "b" | "c"
```

#### `Extract<T, U>` — keep the part of T that overlaps U

```ts
type A = "a" | "b" | "c";
type B = Extract<A, "a" | "c" | "d">;
// "a" | "c"
```

#### `NonNullable<T>` — strip null and undefined

```ts
type A = string | null | undefined;
type B = NonNullable<A>;
// string
```

### 4. Functions: ReturnType, Parameters, ConstructorParameters, InstanceType

#### `ReturnType<T>` — the return type of a function

```ts
function getUser() {
  return { id: 1, name: "Alice" };
}

type User = ReturnType<typeof getUser>;
// { id: number; name: string }
```

#### `Parameters<T>` — a function's parameter types, as a tuple

```ts
function greet(name: string, age: number) {}

type Params = Parameters<typeof greet>;
// [name: string, age: number]
```

#### `ConstructorParameters<T>` — a constructor's parameter types

```ts
class Person {
  constructor(public name: string, public age: number) {}
}

type Params = ConstructorParameters<typeof Person>;
// [name: string, age: number]
```

#### `InstanceType<T>` — the instance type a constructor produces

```ts
class Person {
  name = "Alice";
  age = 20;
}

type P = InstanceType<typeof Person>;
// Person
```

### 5. Building objects: Record

#### `Record<K, T>` — an object type with keys K and values T

```ts
type UserRole = "admin" | "user";

type RoleMap = Record<UserRole, number>;
// same as { admin: number; user: number }
```

## Extras

### `never`

The type that cannot exist — its set of values is empty, so no value belongs to it.

### `infer`

`infer` is how you **declare a type variable to be inferred** inside a conditional type. Putting `infer X` in a pattern says: I do not know what the type in this position is, let the compiler work it out, and hold the answer in `X`.

The rule: `infer` can only appear inside the condition of an `extends`.

```ts
type First<T> = T extends [infer F, ...any[]] ? F : never;
// T extends <pattern containing infer> ? <use the inferred variable> : <fallback>
```
