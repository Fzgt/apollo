# Periplus ② 证据与裁决

> **详解**：[必看 · 证据与裁决](/docs?section=periplus&item=d9-evidence)

## 🔴 今天必看

⚠️ 机制细节以 [Library 的 Periplus AI 笔记](/library?section=periplus&item=ai) 为主。**我这边给口播稿 + 那张分工表。**

**要产出的三件事：**

1. **30 秒口播稿**（草稿在必看篇），出声练
2. **默写六种 Verdict，以及哪四种是模型判的、哪两种是代码判的**
3. **能背出 prompt 里那句英文原话**——引用它比复述强十倍

**六个核心点：**

| # | 要点 |
|---|---|
| 1 | ⭐ **prompt 是请求，不是约束**——而且模型会失败得很自然，编出来的引用读起来和真的一样 |
| 2 | ⭐ **六种判决，模型只允许返回四种**；`stale` 和 `no_evidence` 由应用代码判 |
| 3 | ⭐ prompt 原话（`verification.py:369`）：*"Never decide freshness and never return stale or no_evidence; **application code owns those**."* |
| 4 | ⭐ **`USABLE_VERDICTS = {supported, partial, stale}`**——**`stale` 是可用的**（带时效提醒），不是不能给用户看 |
| 5 | **新鲜度窗口按声明类型分**：价格/营业时间 180 天、可用性/安全 90 天、**位置和描述永不过期** |
| 6 | 代码校验两件确定性的事：**引用的 evidence ID 必须在证据组里**（集合成员检查）、**`as_of` 减发布日期**和窗口比 |

> ⭐ **第 2–3 点是这条 bullet 的全部分量**——`application code — not prompts — enforces` 这句话的字面出处就在那一行 prompt 里。
