---
title: How to Structure a React Component
---

The approach that generalises well: separate container components from UI components.

Extract only the genuinely reusable part into a UI component, and control the different looks through props.

All the logic lives in the container, which nests the UI component inside it. Keep business logic out of the reusable component — it will change sooner or later.

Something like this: one prop decides whether the button reads "Add product" or "Save changes".

Then the container that handles adding and the container that handles editing both call the same UI component.

One more note: in a modern React codebase the container layer usually ends up in a custom hook rather than an actual container component. The separation is the same idea either way.
