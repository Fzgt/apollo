---
title: Reviewing a Full-Stack Stack — tRPC / Zod / React Hook Form
---

Looking back at a full-stack project built on Next.js + tRPC + Zod + React Hook Form, the problems these tools solve turn out to be layered, not overlapping.

#### ① tRPC solves "front-end and back-end types drift apart", and it is not a heavyweight RPC protocol

The RPC in the name suggests something like gRPC — a custom binary protocol, cross-language, heavy. Underneath, tRPC is ordinary HTTP and JSON, indistinguishable in the network tab from a `fetch` you wrote yourself. The magic is entirely **compile-time**: the backend router's type is exported with `export type`, the front end brings it in with `import type` (types only, no runtime code — that import is erased at build time), and the TypeScript compiler follows that chain to infer the shape of what a given procedure returns. The IDE underlines mistakes and the build fails, without anyone hand-writing an interface to describe a response.

The one prerequisite: front end and back end must live in the same repository or monorepo so they can import each other's types. That has nothing inherently to do with Next.js — a separately deployed front end and back end work fine as long as the project is organised that way.

#### ② Zod solves "runtime validation", a different line of defence from tRPC

TypeScript's checking only exists at compile time; once the program is running the type information is gone. Data from outside — form input, API responses, requests from third-party systems — has to be validated for real at runtime. Zod's neat trick is that one schema produces both the runtime validator (`.parse` / `.safeParse`) and the TypeScript type (`z.infer<typeof schema>`), instead of the old arrangement where an interface and a separate validation function slowly drift apart.

Even with tRPC sharing types across the boundary, the server still has to run Zod before it processes a request, because a server can never trust what a client sends: someone may be calling the endpoint directly, the front-end code may be an old version, the network may have mangled something. tRPC is about developer efficiency; Zod is about runtime safety. They are layers, not duplicates.

#### ③ React Hook Form solves "large forms are laggy" by taking typing out of React's render cycle

The traditional approach gives every input a `useState` and an `onChange`, so every keystroke re-renders the whole parent. With enough fields, every keystroke re-renders a large form, and it lags. RHF's core idea is uncontrolled components plus refs: each input registers its DOM node into an internal ref map with `register('field')`, the browser maintains the `value` natively, and typing triggers no React render at all. Only the places that genuinely need the current value — submit, or an explicit `useWatch` subscription — read it back out of the ref map. It is the same instinct as a virtual list: do not do work you can avoid, and only do it when it is actually needed. A virtual list controls the number of DOM nodes; RHF controls how often rendering is triggered.

Pair it with Zod through `zodResolver` and the same schema validates on submit, with errors landing on `formState.errors` — no hand-written validation and no manually stuffing messages into state.
