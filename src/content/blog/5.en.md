title: Understanding `with`
---

### Why look at `with` at all

Vue 2's compiler turns a template into an AST, then a render function, then VNodes. The generated render function uses `with`, and that is where the performance problem comes from.

### Why Vue 2 used it

`with` extends the scope chain, so code inside the block can reach other variables without any ceremony. It made the compiler's job much simpler.

### What it costs

1. `with` turns variable lookup — walking the scope chain — into implicit runtime behaviour. V8 cannot optimise it at compile time.
2. `with` forces every variable of the enclosing function onto the **heap** (into a Context object instead of registers or stack slots), because the engine cannot resolve the references inside the block statically and has to keep the whole scope chain around for runtime lookup. That is a performance cost, not a leak — once the function returns and no closure references it, the Context is collected as usual.

> How the implicit lookup works: check whether the object has the property, and if not, walk up. The walk itself is not slow. The problem is what it prevents:
> 1. the engine will not optimise code inside `with` aggressively;
> 2. the JIT skips deep optimisation of the block;
> 3. inlining, constant folding, and the rest are all disabled.

### `catch` compared with `with`

`catch` also has its own scope, and it also extends the scope chain to introduce the error parameter `e`.

1. `try`/`catch`: TurboFan can still optimise most of the `try` block; it is only conservative on the exception path.
2. `with`: still an optimisation black hole, and the whole scope pays for it.
3. In practice: `try`/`catch` is necessary and the cost is acceptable. `with` is avoidable — Vue 3 dropped it.
