# ③ pgvector 证据缓存与本地向量

> **简历原句**
>
> **Cached evidence embeddings in pgvector** on an **ivfflat cosine index**, generated **locally by MiniLM**.
>
> ---
>
> 证据向量缓存在 pgvector 里，走 ivfflat 余弦索引，向量由本地的 MiniLM 生成。

## 这条要讲清什么

一句话：同一段证据不重复抓、不重复算向量，而且算向量这件事不花钱、不出网。缓存是按意思像不像命中的，不是按 URL。

## 缓存的键是什么，为什么不按 URL

按向量相似度。同一件事会散在不同站点、不同 URL、不同标题下；按 URL 只能挡住抓过完全相同的那一页，挡不住「这段话我已经有了」。

向量的意思是把一段文字变成一串数字，意思相近的文字数字也相近。于是「有没有和这段话意思差不多的东西」变成了一个可以用数据库回答的问题。

表里存的是规范化的键、URL、标题、正文、来源类型、发布日期、抓取时间、当时的查询词，还有那一列三百八十四维的向量。三百八十四是那个向量模型的输出维度，而向量列类型本身是 pgvector 提供的。

## 本地生成向量是什么意思，为什么重要

用的是一个约八十兆、三百八十四维的小模型，跑在 CPU 上，走 sentence-transformers，不调任何付费的向量接口。

这条和[脚本化接缝](/docs?section=periplus&item=scripted-seams)那条是同一个立场的两面：整个系统能在没有 API key、没有网络的情况下跑完。向量如果要联网算，那句话就不成立了。

顺带一个成本口径：检索阶段可能抓几十个页面，每个都要算向量。走接口就是每次运行都在为「我可能已经有了」付钱。

## 查询长什么样，余弦体现在哪

查询是取距离最近的一条，然后在应用层把距离换算成相似度并卡一个阈值，默认是零点九。pgvector 提供了一个余弦距离运算符，排序和取值都用它。

为什么用余弦不用欧氏距离：余弦是语义相似度的惯例选择，而且对向量长度不敏感——两段话意思一样但长短不同时，余弦仍然判它们近。

为什么要卡阈值而不是取最近的就用：取最近一条永远会返回某一行，哪怕库里最像的那条其实毫不相干。阈值是把「最近邻」变成「够像」的那一步，少了它就会拿错误的缓存冒充证据。这一句是这条最该讲的，因为它是个正确性问题不是性能问题。

## ivfflat 和那个簇数是什么

ivfflat 是一种近似最近邻索引：把向量空间切成若干个簇，查询时只扫最近的几个簇，而不是全表比一遍。索引建的时候指定切成一百个簇。

这个数怎么定的，要诚实答：一百是常见起点，代码里没有写调优依据，被问到就说是默认值、没有实测过。

为什么用 ivfflat 不用 HNSW，代码里也没有给理由。可以这样答：我的理解是 ivfflat 建索引快、占内存小，适合这种写入频繁、行数中等的缓存，HNSW 查询更快但建索引慢、吃内存；说清这是权衡，不是定论。

不知道就说不知道，在这两处尤其成立——它们都是可以查证的实现细节，编一个理由被追一层就崩。

## 空库怎么办

这是这条最好的一个细节，注释直接写了：ivfflat 需要训练数据才能建出有用的簇；一张空的或接近空的表——也就是每一个刚建好的数据库——只会得到一个单簇的索引，在积累够行数之前它退化成全表扫描；那是一个正确但慢的索引，绝不会给出错的答案。

宁可慢也不能错，这个价值观和[证据判断那条里「宁可没有日期也不要猜一个」](/docs?section=periplus&item=evidence-judgment)是同一个。这两处放在一起讲，比单说一个有说服力。

## 数据库挂了会怎样

缓存整体是尽力而为的：算向量失败或者数据库出错时，返回「没找到相似的」，而不是抛异常。注释里那行的意思是——一次缓存故障必须降级，绝不能让整个运行崩掉。

所以 PostgreSQL 抖一下只会导致重复抓一次页面，不会让整个运行挂掉。

连接池另外配了取连接前先 ping 的检查，坏了就换一条。理由是：反正下游已经吞异常了，与其付一次注定失败的往返再白白 miss，不如先 ping。

## 概念补充

**缓存怎么失效。** 不设过期时间。失效是在消费的时候按日期判断的，走[新鲜度窗口](/docs?section=periplus&item=evidence-judgment)那一套。这个区分值得主动说：缓存不负责判断新不新鲜，只负责别重复干活；新鲜度是业务语义，归判断过期的那个函数管。

**为什么只拿前两千字算向量。** 两个理由，注释都写了：那个向量模型本身只关注大约前两百多个 token，再多喂给它也不会改变判断；而把每个抓到的页面全文无限期存下来，会让这张缓存表变成库里最大的表，却换不来任何匹配收益。存两万四千字是给下游用的正文，算向量只用前两千字——两个上限服务两个不同目的，别说成一个。

**为什么整个进程共用一个实例。** 注释说得很直白：这个缓存的价值完全来自被很多次运行查到，而不是每次运行重建一次。打开和关闭括住连接池的生命周期，一个实例活整个进程。

## 英文怎么说

一句最该背的是空库那条注释：that is a correct, if slow, index — never a wrong answer。它同时展示了取舍判断和价值排序。

其他常用词：向量是 embedding，向量检索是 vector search，余弦相似度是 cosine similarity，近似最近邻是 approximate nearest neighbour 简称 ANN，索引退化成全表扫描是 degrades to a full scan，优雅失败是 fail soft，相似度阈值是 similarity threshold，尽力而为是 best-effort，连接池是 connection pool。

## 30 秒回答

> 检索阶段会抓很多页面，同一件事经常散在不同 URL 下，所以证据缓存不按 URL 命中，按语义命中。每段证据存一条三百八十四维向量，向量由一个小模型在本地 CPU 上算，不调任何付费接口——这样整个系统才能在没有 key、没有网络的情况下跑完。查询用 pgvector 的余弦距离运算符取最近的一条，再卡零点九的相似度阈值，因为取最近一条永远会返回一行，阈值才是把最近邻变成够像的那一步。索引是 ivfflat 余弦，一百个簇。空库上它退化成全表扫描，注释里那句我很喜欢：那是一个正确但慢的索引，绝不会给出错的答案。整个缓存是尽力而为的，数据库出问题就当没命中，只多抓一次页面，不会让运行挂掉。
