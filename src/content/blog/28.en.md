title: Why Did You Render
---

## What it solves

`React.memo` and `PureComponent` decide whether to skip a render by shallow-comparing props and state. There is a quiet trap in that: **if you pass an object, array, or function, an identical value with a different reference still compares as changed, and the component re-renders anyway.**

```javascript
<BigList style={{ paddingTop: 350 }} /> {/* a brand new object on every parent render */}
```

The contents of `style` never change, but because it is a new object each time, `memo` decides it changed and re-renders for nothing. This kind of bug logs no error, looks fine on screen, and is very hard to spot by eye.

**why-did-you-render finds these invisible wasted renders and prints them to the console.**

---

## How to use it, in three steps

### Step 1: install

```bash
npm install @welldone-software/why-did-you-render --save-dev
```

### Step 2: create a dedicated init file, development only

```javascript
// wdyr.js
import React from 'react';

if (process.env.NODE_ENV === 'development') {
  const whyDidYouRender = require('@welldone-software/why-did-you-render');
  whyDidYouRender(React, {
    trackAllPureComponents: true, // track every component using memo/PureComponent
  });
}
```

**⚠️ The docs are explicit: never use it in production.** It monkey-patches React's internals to record comparisons, which costs performance. It is purely a development tool.

### Step 3: make it the very first import in the app

```javascript
// index.js
import './wdyr'; // ← must come first
import React from 'react';
import ReactDOM from 'react-dom';
```

---

## Two ways to track specific components

**Option 1 (recommended)**: `trackAllPureComponents: true` tracks everything using `memo` or `PureComponent`, with nothing to mark by hand.

**Option 2**: mark the suspects yourself

```javascript
class BigList extends React.PureComponent {
  static whyDidYouRender = true;
  render() { ... }
}

// same for function components
const BigListPureComponent = (props) => <div>...</div>;
BigListPureComponent.whyDidYouRender = true;
```

---

## What you get

When it detects a render that could have been avoided, the console prints something like:

```
Main was "re-rendered because of props changes"
    style has received different objects that are equal by value:
    {paddingTop: 350} !== {paddingTop: 350}
```

It tells you **which component and which prop**, and that the values are equal but the references are not — at which point whether to wrap it in `useMemo` or hoist the object out of the component is obvious.

---

## In one sentence

> It is not a tool for *avoiding* re-renders — that is what `memo`, `useMemo`, and `useCallback` are for. It is a development-only detective that finds the cases where `memo` or `PureComponent` was applied but a fresh reference threw the optimisation away, and points at the exact prop, so you do not have to hunt.
