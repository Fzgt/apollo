# Pixels and the viewport

## 1. Physical pixels vs CSS pixels

| Concept | What it is |
|---|---|
| **Physical pixel** | A real light-emitting dot on the screen. Fixed in hardware — an iPhone 6 panel is 750×1334. |
| **CSS pixel** | The logical unit you write code in, as in `width: 100px`. |

- To display a page, the browser converts **CSS pixels** into **physical pixels**.
- How many physical pixels one CSS pixel ends up as is decided by the browser, through the device pixel ratio (DPR).
- **On desktop, by default**: 1 CSS pixel = 1 physical pixel (DPR = 1).

---

## 2. The viewport

- The viewport is the area of the screen the page is drawn into — the browser window.
- Its **width** (width only; height does not matter here) is what tells you the ratio between CSS pixels and physical pixels.
- The viewport's child is `html`, and with no zoom, the width of `html` equals the width of the viewport.

### Zoom, worked through

- The physical width is fixed: **1920px**. It never changes.
- Zoom in 2×, and the viewport width in CSS pixels becomes **960px**.
- So CSS pixels : physical pixels = **1 : 2**.

> What zoom really changes is the **ratio** between CSS pixels and physical pixels, not the physical pixels themselves.
> Change the size of the viewport and you change that ratio.

---

## 3. Phone pixels and mobile adaptation

- The physical size of one pixel differs from screen to screen: the smaller the dot, the sharper the display.
- Pixels on a smartphone are usually far smaller than pixels on a desktop monitor.

### The problem

> How does a 900px-wide page display on an iPhone 6 (4.7 inch, 750×1334 physical pixels)?

- **Mobile browsers default the viewport to 980 CSS pixels**, so that pages written for desktop still render on a phone.
- If the page is wider than 980px, the phone scales it down to fit.
- The result: most desktop pages will "show up" on a phone, but the experience is usually poor.

---

## 4. The perfect viewport

- Default mobile viewport: **980px** in CSS pixels
- Default ratio: **980 / device width** — 980 / 750 on an iPhone 6, which is not a good number
- If you write mobile-specific code but stay on the 980 viewport, everything on the page comes out tiny.

### The fix

Set the viewport yourself with a `meta` tag, so that **one CSS pixel maps to a sensible number of physical pixels** (1:2, for example):

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

- Every mobile device ships with an **officially recommended DPR**.
- Set the viewport to that ratio and you have the **perfect viewport**.

---

## 5. The `vw` unit

```
100vw = one viewport width
1vw   = 1% of the viewport width
```

- `vw` is always relative to the **viewport width**. It is the usual tool for responsive mobile layouts, where elements scale proportionally with the screen.

### Design file sizes (by DPR)

| Scale | Canvas width | DPR |
|---|---|---|
| 2× | 750px | DPR = 2 |
| 3× | 1125px | DPR = 3 |

### Converting px to vw

```
vw = (px in the design file / total design width) × 100
```

**Example**: the design is 750px wide and a button is 75px wide.

```
75 / 750 × 100 = 10  →  width: 10vw
```

---

## Putting it together

```
Physical pixels (fixed in hardware)
   ↓
DPR decides how CSS pixels map onto physical pixels
   ↓
Viewport width decides how many CSS pixels the page has to work with
   ↓
The 980px mobile default is wrong for a hand-written mobile page
   ↓
Use a meta tag to set the "perfect viewport" (width=device-width)
   ↓
Then use vw to scale proportionally against the 750/1125 design file
```
