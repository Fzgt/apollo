# 每日产出标准

每条 bullet 至少四项产出：

1. **30 秒「人话版」** —— 非技术 recruiter 也听得懂，先讲用户问题和结果，别堆 API 名
2. **2–3 分钟 STAR / 技术版**
3. **技术追问清单** —— 每个问题都要有答案，答不上的当场标出来
4. **至少一个「为什么不用其他方案」**

## 讲述链路

> 背景 → 我做了什么 → 为什么这么做 → 技术原理 → trade-off → 结果如何测量 → 重做会怎么改

## Day 8 起的前置动作

先按当天的「必读代码」清单打开文件读完，**再动笔写讲法**。讲法里出现的每一个类名、枚举值、文件位置都要和代码对得上。

## 完成标准

- 任意 bullet 能先用 30 秒讲成人话
- S 级 bullet 能连讲 3–5 分钟不靠背稿
- 每个架构选择都有替代方案和 trade-off
- 每个异常场景都有失败处理和恢复策略
- 每个数字都能说清来源、测量方式和归因范围
- **讲到自己代码时，类名、枚举值、文件位置和仓库一致**
- 从简历任何一句切入，都能往下再解释两层

## 页面里的状态怎么用

每篇笔记的 frontmatter 有一行 `status`，改它，总览页的进度看板自动更新：

- `todo` —— 还没开始
- `doing` —— 今天在做
- `done` —— 四项产出齐了、追问答完了
