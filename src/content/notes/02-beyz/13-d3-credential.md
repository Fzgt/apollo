# Day 3 · 凭证（速查）

> ⚪ **这半条 Day 1 已经学完**：[#1 · 60 秒临时凭证](/docs?section=numbers&item=n01-ephemeral-keys)（为什么 60 秒 / 谁签发 / 续签 / scope）· [#1 补充 · keepAlive](/docs?section=numbers&item=n01b-keepalive)（10 秒心跳）。
>
> 这里只补那两篇没有的三块。

## 一、长期 key 下发到浏览器会怎样

**浏览器里没有秘密**——F12、`localStorage`、内存变量全是明文。混淆加密都没用，**代码要用它，用的那一刻就是明文**。

| 后果 | 说明 |
|---|---|
| **无限期盗用** | 没有 TTL，**泄露一次就是永久泄露** |
| **账单被打爆** | 拿你的额度做任意转写 |
| **提权** | 长期 root key 通常带管理权限——能读项目、看账单、**再铸新 key** |
| **吊销代价极高** | 所有用户共用它，**一吊销全线中断**，还得发版换 key |

> **最后一条最能体现理解**：临时凭证真正买到的不只是「泄露损失小」，而是**「不需要吊销」**——它自己会过期。

## 二、TTL 过期时用户正在说话怎么办

**什么都不会发生。** TTL 管的是「**用这把 key 建立连接**」，不是连接的存活时间。握手完成后 socket 已经立住，key 过期与它无关。

> **代码内部自证**：每 10 秒 keepAlive 是为了防空闲超时——**如果 key 过期会杀连接，这套 keepAlive 毫无意义**，所有面试都会在第 60 秒整齐挂掉。
>
> **两条生命周期别讲混**：60 秒管**凭证**（能不能建新连接），10 秒管**连接**（会不会被空闲踢掉）。**把 keepAlive 说成「续期 key」就露馅。**

## 三、三个概念框架

**authn vs authz**（`route.ts:10-13` 那三行同时做了两件事，**顺序不能反**）：

| | 问题 | 对应 |
|---|---|---|
| **Authentication** | **你是谁？** | `getAuthUser()`，认不出直接 throw |
| **Authorization** | **你能干什么？** | `subscribedPlan === Free → 拒绝` |

而下发的临时 key 是第三层——对 Deepgram 而言它是个 authorization 凭据，`scopes: ["usage:write"]` 精确描述持有者能干什么。

**TTL / scope / 吊销是同一个设计的三个旋钮**：

| 旋钮 | 这里取值 | 调它的代价 |
|---|---|---|
| TTL | 60 秒 | 太短误伤慢网络下的正常握手 |
| Scope | `["usage:write"]` 一个 | 太窄功能不可用 |
| 吊销 | **不需要**——自己过期 | 长期 key 才需要，代价是全线中断 |

> **TTL 和 scope 是事前压小爆炸半径，吊销是事后止损。临时凭证的价值在于把问题从「事后」挪到了「事前」。**

**滥用防护的缺口**：⚠️ 这个路由**没有任何限流**（grep 不到 `ratelimit`），付费用户能无限刷。**60 秒 TTL 只是缓解**（key 自动回收），真正该加按用户的速率限制。
