# ① 二十个场景与一次开局的种子

> **简历原句**
>
> Built a browser racing game: steer a craft through **fields of neon obstacles across twenty scenes**, with the **terrain, skyline and obstacles all generated on the fly from how far you have traveled**, on a **fresh seed each run**.
>
> ---
>
> 做了一个浏览器竞速游戏：驾驶飞行器穿过二十个场景里的霓虹障碍场，地形、天际线与障碍全部按已行驶里程实时生成，每局一个新种子。

## 这条要讲清什么

三件事，一句话各一个。二十个场景是世界的编排，按里程生成是这些内容怎么来的，每局一个新种子是为什么两局不一样。手工摆场景做不出这个规模，所以全部是行驶距离的函数。

## 场景和关卡不是一回事

这是两套独立的进度轴，都按一千八百个世界单位推进，但含义完全不同。

关卡只管调色板和速度，一共六个，循环使用，越跑越快，所以这局是无尽的。场景管的是轨道两侧站着什么——霓虹城、灯塔海岸、深渊隧道、铁港、守望者、极光峡谷，一直到第二十个终局。

关键差别在于场景不循环。取索引的时候用最小值把它钉在最后一个上，所以跑过终点场景之后，世界停在它的余晖里，不会绕回第一个场景。关卡循环是为了无尽，场景不循环是为了「你确实走到了尽头」——这一句是这两条轴的设计意图，被问「为什么一个循环一个不循环」的时候直接答。

## 按里程生成具体指什么

指世界里几乎所有东西都是行驶距离的函数，没有预先摆好的关卡文件。

景是按世界瓦片重建的：跨过一个边界就把身后那一段丢掉，在前方按那一段归属的场景建下一块。静态部分合并成少数几个绘制调用，活的东西——鱼、鲸、水母、飞艇、踱步的战争机器、涡轮转子、灯塔光束——是小的实例化网格，逐帧动。

障碍生成更彻底。原来是四种命名编队：散布、门阵、回转、柱林，每两千单位换一种。废掉的理由写在代码注释里，一句话：每一种编队只能给人惊喜一次。

现在没有编队，只有三个连续函数，每隔一个固定深度采样一次。第一个是通道，也就是保证能过去的那条路，它的摆动速度不超过飞行器在那个速度下能横移的距离。第二个是压力，也就是这一段的密度有多高。第三个是低矮和高耸的配比，决定这一段是能看过去的宽矮块，还是要绕过去的窄高块。

三条都是周期不同的平滑噪声，所以它们各自进出相位，没有哪一段像前一段；而且三条都不知道分段边界在哪，接缝因此消失。这一句是这部分最该讲的——接缝不是修掉的，是因为没有任何一条函数知道边界在哪，所以边界根本没产生。

## 每局一个新种子解决的是什么问题

是行驶距离的函数，就意味着每局是同一条路。这是上一版的真实缺陷，注释说得很直白：方块在两局之间的确会挪位置，因为每个方块的摆放都掷了一次没有种子的骰子；但形状没变——通道在同一个位置横穿场地，密集的结在同一批切片里，密度在同样的地方达到峰值。一个玩家在同一段死两次，遇到的就是同一段。

修法是把整个场地挂在一个整数上，模块加载的时候抽一次，也就是每局一次，因为重开会重新加载页面。这个种子被折进所有噪声流共用的那个哈希函数里，一处就把通道、压力、高低配比、护栏和事件全部重新播种。

为什么用异或折进去而不是加：异或是一一映射，不同的种子折完仍然不同，所以不会把几条流意外拉到同一个相位上去。这一问偶尔会来，答得出来说明你知道自己在做什么。

## 只换种子够不够

不够，这是这条最值得讲的一层。注释里那句话很准：从同一个分布里抽两次，从驾驶舱里看是一样的，因为眼睛报告的就是那个分布。

换种子只换到「这局拿到哪些方块」，换不掉「这是哪种路」。洗过的牌还是同一副牌。

所以又拿一部分常量当这局的性格，每一个都是从这局的种子上掷一次、整条路握住不变。周期决定一种风格能持续多长，浮动正负四成——有的局几百单位就换一次主意，有的局大半个分段只认一个调子。配比决定这条路是宽矮的板还是细高的塔。走廊决定这局的通道大致偏宽还是偏窄。护栏比例决定多大比例是沿通道成墙，而不是散在四周。

性格和排列的区分，是这条 bullet 真正的技术点。被问「换个随机种子不就完了吗」，答案就在这里。

## 换了种子，公平性保证还成立吗

成立，而且正是因为这个才要留一个重新播种的入口。

那个入口游戏本身从不调用——重开会重新加载页面，模块在加载时自己抽种子。它存在只为让公平性扫描能走很多条路，而不是在同一条路上掷很多次骰子。扫描的结论在关卡可通过性那一篇里。

注意它必须做的清理：所有按行驶距离记忆化的东西都要跟着清掉。通道的采样是从起跑线一路走出来的，缓存的展度是从那些采样读的，不清就会拿旧路的数据去解释新路。这个细节被问到能答出来，说明你真的写过这个函数。

## 概念补充

**为什么不做手工关卡。** 二十个场景加上无尽的里程，手工摆的成本是线性增长的，而玩家一局只看得到其中一段。函数生成的成本是常数，而且能保证接缝处是连续的——手工关卡的边界永远是硬接。代价是可控性变差，所以才需要那套公平性扫描当回归测试。

**平滑噪声为什么用不同周期。** 同周期的几条噪声会同时到峰值，世界就变成一阵很密、一阵很空的节拍。周期错开之后它们进出相位，组合出来的形态不重复——这是用很少的参数拿到「看起来没有规律」的标准做法。

**把场景索引钉在最后一个有什么代价。** 跑过第二十个场景之后世界不再变化。这是刻意的，但意味着很长的一局后半段视觉是静止的，只有关卡的调色板还在循环。想继续给变化，要么加场景，要么让场景也循环——那就丢掉「终点」这个叙事。

## 30 秒回答

> 这是个浏览器里的竞速游戏：开一台飞行器穿过霓虹障碍场。世界不是手工摆的关卡，是里程的函数——每一千八百单位换一个场景，一共二十个，跑到第二十个之后不循环，世界停在终局的余晖里；调色板和速度是另一条轴，六种循环，越跑越快。障碍场没有预设编队，由三条周期不同的平滑噪声决定：保证能过的通道、这一段的密度、以及这段是宽矮块还是窄高块。因为全是里程的函数，第一版每局都是同一条路，所以我把整个场地挂在一个每局抽一次的种子上，用异或折进所有噪声流共用的哈希。光换种子只换到方块排列，所以另外拿几个常量当这局的性格——周期长度、板和塔的配比、通道宽窄、成墙比例——让两局是不同的路，而不是同一副牌洗一次。

## 英文怎么说

「排列」和「性格」这组区分是这条最该讲对的英文：a new seed only changes which blocks you get; the personality constants change what kind of route it is。编队被废掉的理由直接引原话 every formation is a surprise exactly once。「同一副牌洗一次」说 a shuffled deck is still the same deck。其他常用词：程序化生成是 procedural generation，种子是 seed，重新播种是 reseed，平滑噪声是 smooth noise，相位是 phase，接缝是 seam，通道是 lane 或 corridor，缓冲密度是 pressure，实例化网格是 instanced mesh，绘制调用是 draw call，余晖是 afterglow。
