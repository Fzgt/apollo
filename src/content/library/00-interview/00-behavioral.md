# 通用行为面准备（对应简历 v40）

> 2026-08-18 写。这是**参考稿**，不是定稿——里面凡是标 `【只有你能填】` 的地方，
> 我不知道事实，不替你编。其余部分全部只用 v40 简历上已有的事实和你自己代码里的东西。
>
> 已有的 `Coreflow_自我介绍准备.md` 是 8/4 那场电话面的，绑死在那家公司、口径也早于 v40。
> 这份是通用底稿，面某一家之前再往上叠公司专属的那一层。

---

## 0. 行为面的基本规矩

- **前十分钟不会问技术。** 问的是：你是谁、为什么来、为什么走、和人怎么处。技术准备再厚，这十分钟垮了就没有后面。
- **每个故事一个结构**：Situation → Task → Action → **Result** → Reflection。九成人死在 Result 上——讲了半天做了什么，没说结果是什么。
- **一个故事最多 2 分钟。** 讲完停住，让对方追问。自己一路讲到底的人显得听不懂气氛。
- **不说别人坏话。** 前公司、前同事、前老板，一句都不要。评价前雇主的方式是讲事实和自己的判断，不带情绪形容词。
- **不确定的事说不确定。** 澳洲面试官对"编"的容忍度比国内低得多，被抓一次整场就废了。

## 1. 自我介绍

### 30 秒版（电话初筛、HR 开场）

**中文**

我是全栈工程师，大概四年商业经验，主线是消费级产品的前端和全栈——在百度做过日活过亿的产品，
在 BioMap 主导过核心产品的前端架构，最近一段在一家 AI 创业公司独立负责了完整的实时功能链路和付费转化。
去年在悉尼科技大学读完了 IT 硕士，这两年把重心移到了 AI 工程——最近自己做的一个项目是把 LLM 的输出
全部绑到可核查的证据上，并且给它建了离线评测。我现在想找的就是这个方向的岗位。

**English**

I'm a full-stack engineer with about four years of commercial experience, mostly on consumer-facing
frontend and full-stack work. At Baidu I worked on products with over a hundred million daily users;
at BioMap I led the frontend architecture of the core product; most recently at an AI startup I owned
the real-time pipeline and the paid conversion path end to end. I finished my Master's in IT at UTS
this June. Over the past two years I've moved toward AI engineering — my latest project grounds every
LLM claim in a verifiable source quote and scores the whole pipeline against an offline golden set.
That's the kind of role I'm looking for now.

### 90 秒版（正式面开场）

四段，每段一句话打底，别展开：

1. **我是谁 + 规模跨度**：四年，从日活过亿的大厂产品，到七人的早期创业公司，再到远程独立负责一整块。
   规模跨度本身就是卖点——**大厂教你怎么不出事，小厂教你怎么把事做完**。
2. **我最近在做什么**：AI 工程。不是"调了个 API"，是把不可靠的模型输出变成可核查、可测量的系统。
   Periplus 那句可以直接用：证据和裁决分开，代码而不是 prompt 来强制引用和时效。
3. **我为什么擅长这个**：因为我在百度处理过高并发和线上事故，知道"能跑"和"能上线"差多远。
   AI 系统最缺的正好是这个——大部分人做到 demo 就停了。
4. **我想要什么**：说这家公司的方向，一句话。【只有你能填：按公司定制】

## 2. 时间线上必被问的四件事

面试官手里就一张纸，他会盯着日期问。**这四个必须有准备好的答案，不能临场想。**

### ① 2022 年 10 月到 2024 年 1 月这十五个月

`【只有你能填】` 我不知道这段发生了什么，不替你编。

**答的骨架**（把事实填进去就行）：
> 那段时间我在 [做什么]。之所以没有立刻找下一份工作，是因为 [原因]。
> 这段时间里我 [具体做了什么可验证的事]。回头看，[它给了我什么 / 我会怎么调整]。

**三条规矩**：
- **不要道歉**，不要说"很遗憾那段浪费了"。空档在澳洲市场极其常见，防御姿态才可疑。
- **给一个具体的事实**，哪怕小：备考、学习、家庭、身体、准备留学申请、疫情。具体永远比"调整状态"可信。
- **落回现在**：一句话说明你现在的状态是稳定的、可以长期投入的。

### ② 百度 10 个月、BioMap 7 个月，两段都不到一年

这条一定会被问，而且是"你会不会又跑"的试探。

**答的骨架**：
> 百度那段是 [离开原因 —— 只有你能填]。BioMap 那段是 [离开原因 —— 只有你能填]。
> 这两次都不是因为和人处不来，也不是因为活干不下去——我在百度是第一个定位到那次 P2 白屏的，
> 在 BioMap 是主导架构的那个人。之后我出来读了硕士，这是我当时就计划好的，
> 所以那两段的长度是被留学时间线切开的，不是我坐不住。

**关键**：把"短"归因到一个**可解释的外部时间线**（留学），并且用两个"我在那儿是负责的人"的事实压住"是不是干不好"的怀疑。
如果真实原因不是这个，就换成真实的——但结构不变：**原因 + 我在那儿做成了什么 + 现在的稳定性**。

### ③ Beyz 是 2024 年 1 月到 10 月，你 8 月已经在 UTS 了

时间上有两个月重叠，纸面上看得见，别等他问。

**答**：
> Beyz 是加拿大的公司，我是远程的。开学那两个月是重叠的，我把它做完交接清楚才结束——
> 这也是为什么那段是 10 月结束而不是 8 月。

**如果被追问"边读书边全职做得过来吗"**：正面回答，不要辩解。说清楚当时的实际安排（几小时、怎么排优先级），
然后主动给出结果证据：那段时间交付的是完整的实时链路和付费链路，不是零碎任务。

### ④ 硕士 2026 年 6 月毕业，现在是 8 月

两个月的空窗，不算长，但要有话说。

**答**：毕业后这段时间我在 [做 Periplus / 找工作 / 【只有你能填】]。
可以直接把 Periplus 拿出来当证据——**手上有正在写的代码，是求职期最好的状态证明**。

## 3. "为什么转 AI" —— 这是你的主线问题

这个问题问的不是兴趣，是**可信度**：一个做了四年前端的人说要做 AI，凭什么？

**不要答**："AI 是未来"、"我对大模型很感兴趣"、"我自学了很多课程"。这些谁都能说。

**要答**（三步，每步一个事实）：

1. **不是从零转，是往上长。** 我在 Beyz 做的实时面试助手已经是 LLM 应用了——流式识别、
   token 逐个吐、按用量计费、并发生成的状态机。那时候我发现最难的不是调模型，是**模型之外的一切**。
2. **所以我去做了那个"之外的一切"。** Periplus 整个项目就是围绕这个：证据和裁决分开，
   引用和时效由代码强制而不是 prompt 请求，运行状态持久化到能从中断处恢复，
   每个外部依赖后面都有一条可替换的接缝，所以整套系统不用 API key 不用网络就能跑完 406 个测试。
3. **我带过来的东西正好是这个领域缺的。** 我在百度处理过日活过亿的线上事故和高并发，
   知道"跑通"和"敢上线"之间差什么。AI 团队里做 demo 的人很多，**能把 demo 变成可回归、可归因、
   出事能查的系统的人少**——那就是我。

**收尾一句**（这句很值钱）：
> 我最不想做的是那种"改了 prompt 感觉变好了"的工作。所以我给自己的项目建了 golden set，
> 每次改动都能出一张逐指标的 before/after 表。这是我理解的 AI 工程和 AI 调参的区别。

## 4. STAR 素材库 —— 一个故事对应哪几个问题

**同一个故事可以答多个问题，但一场面试里不要重复用同一个。** 下面每条都标了它最适合答什么。

| 素材 | 一句话 | 最适合答 |
|---|---|---|
| **百度 P2 白屏** | 一亿 DAU 的搜索页白屏，我第一个定位到是 Node 版本不一致重新生成了 lockfile、拉进一个破坏性小版本升级，之后推动了版本锁定和发布前检查 | 压力 / 主动性 / 从失败中学到什么（流程层面）/ 你如何排查一个没人知道原因的问题 |
| **百度 Webpack 3→5** | 十几个不兼容的包，分阶段迁移，抽公共运行时、开持久化缓存，包体积 -15%、本地构建 -70% | 长期技术债 / 如何说服团队投入没有直接业务价值的事 / 如何拆解一个大任务 |
| **百度提现 2000 QPS** | 请求锁 + 防御式兜底，峰值下没有一分钱损失 | 风险意识 / 在正确性和速度之间怎么选 / 你做过最谨慎的一个决定 |
| **百度虚拟列表** | 自己写 useVirtualList，DOM 从 500+ 降到 20 左右，滚动从 30 FPS 稳到 60 | 你最自豪的技术工作 / 如何量化一个体验问题 |
| **BioMap ESLint 边界** | 用自定义 lint 规则把模块边界变成会失败的检查，而不是文档里的约定 | 如何推动团队规范 / 和同事有分歧怎么办 / 你如何影响没有汇报关系的人 |
| **BioMap TanStack Query 三层** | API 函数 → queryOptions 工厂 → 类型化 hooks，单一缓存键、失效由 mutation 驱动，详情页 LCP < 500ms | 架构决策 / 为什么这么设计而不是更简单的做法 |
| **Beyz 实时链路** | 标签页音频 → WebSocket → 流式识别 → 句末事件触发 → token 逐字回吐 | 你做过最复杂的一个东西 / 端到端负责的经历 |
| **Beyz 权益只由 webhook 写** | 用户跳回 success_url 不等于钱到账，唯一可信的事实源是签名事件 | 你如何处理"看起来能用但其实不对"的方案 / 正确性优先的取舍 |
| **Beyz 独立做邮件服务 + 首个 CI** | 没人要求，我看到定时任务需要常驻进程，拆出独立服务；顺手给仓库加了第一道 CI 关卡 | 主动性（最好的一条）/ 你如何在没有明确任务时找事做 |
| **Periplus 证据与裁决分离** | 出证据的和判对错的不是同一个阶段，且由代码而不是 prompt 强制 | 系统设计 / 你如何处理不可靠的输入 |
| **Periplus golden set** | 冻结 brief、语料和时钟，只断言范围不断言字面输出，每次改动出 before/after | 你如何知道自己改好了 / 质量意识 / 你最近学到的东西 |
| **WinterFell 雾导致整帧卡死** | 每次换配色都卡一帧，查到是 JSX 声明的雾对象被重建，而雾属于材质的 program key，导致整个场景的材质在一帧内全部重编译 | **"讲一个你自己造成的 bug"** / 你如何验证一个假设（我写了个探针数每帧新建的管线数） |
| **WinterFell 实例化的代价** | 合成两个 InstancedMesh，draw call 129→76，但代价是丢了逐实例视锥剔除 | 你如何主动交代自己方案的缺点 / trade-off |

**注意 WinterFell 那两条**：它们是你**自己拿工具量出来的**，可信度最高。行为面里"你怎么验证的"这类问题，用它们最硬。

## 5. 高频题的答法骨架

### 「讲一次你和同事的分歧」
**不要**讲成"最后证明我是对的"。那是最差的版本。
**骨架**：分歧是什么 → 我先去搞清楚他的理由（这一步必须有）→ 我拿出的是什么证据不是什么态度 →
结论是什么（**可以是我被说服了，那样反而加分**）→ 之后我们怎么定的规矩。
**可用素材**：BioMap 那条 ESLint 边界。核心句：**"我不想靠 code review 里反复提醒来维持边界，所以把它变成一条会失败的检查。"**

### 「讲一次你失败的经历 / 你犯过的错」
最容易假的一题。**必须是你自己的错，不能是别人的、不能是环境的。**
**推荐用 WinterFell 那个雾的 bug**：是我自己写出来的（把 fog 声明成 JSX，每次配色变化都重建对象），
表现是每次换配色卡一整帧，我一开始怀疑的方向是错的，最后靠一个数每帧新建管线数的探针才确认。
教训是：**声明式框架里，"看起来只是描述"的东西可能每帧都在重建，而它可能挂在别人的缓存键上。**
**次选**：Beyz 的 Stripe webhook 没有做 event id 去重表，靠的是收敛写（每次都置成目标状态）——
这是个"我知道它不够严、现在还没补"的诚实答案，比编一个完美收场的故事强。

### 「你最大的弱点」
**不要**用伪装成优点的弱点（"我太追求完美"），面试官一天听八遍。
**骨架**：一个真实的、和这个岗位不致命的弱点 + 你已经在做的具体动作 + 一个可见的进展。
**可用的真实素材**：测试。你两个商业仓（beyz-web / beyz-server）都没有测试文件，这是事实。
可以说：我以前把交付速度排在测试前面，Beyz 那两个仓我只加了 lint/typecheck/build 的 CI，没有测试。
后来自己做 Periplus 时我反过来了——先把所有外部依赖做成可替换的接缝，让 406 个测试能在一秒内无网络跑完。
**这个答案的好处**：真实、有改进证据、而且顺势把话题带到你最强的那条 bullet 上。

### 「你为什么想来我们公司」
`【只有你能填 —— 每家都要重写】`
**骨架**：他们在做的一件具体的事（产品/技术/开源仓）→ 它和我做过的什么对得上 → 我能带进来什么。
**红线**：不要说"贵公司平台大"、"能学到很多"。求职者说"能学到很多"，听起来像"我来消耗你们的资源"。

### 「你未来三到五年怎么规划」
**骨架**：往深不往宽——继续做 AI 系统工程这一层（评测、可靠性、成本、可归因），
从"能把系统建起来"到"能定义一个团队的质量标准"。**不要说想转管理**，除非这岗位就是往那走。

### 「你怎么处理压力 / deadline」
用百度白屏那条。**重点不是"我抗压"，是"我在压力下的动作顺序"**：先止血（回滚/降级）再定位根因，
定位之后立刻把它变成流程（版本锁定、发布前检查），保证不会再来第二次。

### 「你怎么和非技术的人协作」
`【只有你能填 —— 你有没有具体的产品/设计协作故事】`
可用的通用点：MSW mock 层那条——**让前端交付不依赖后端进度**，本质就是解决协作阻塞。

## 6. 你要反问的（一定要问，问不出来等于不关心）

**留三到四个，按对方是谁挑：**

**问工程负责人 / 技术面官**
1. 你们现在怎么判断一次 prompt 或者模型的改动是变好了还是变差了？有离线评测吗，还是靠人看？
   （**这题是你的主场**——不管他答什么，你都有 Periplus 的做法可以接上）
2. 线上出问题的时候，从用户报错到定位到具体是哪个环节，通常要多久？
3. 这个岗位进来的头三个月，你希望他把什么事情做成？
4. 代码 review 和测试目前是什么状态？CI 卡哪几道？

**问 HR / 招聘经理**
5. 团队现在多少人，这个岗位是补缺还是扩编？
6. 接下来的流程是什么，大概多久？

**永远不要在第一轮问**：薪资、加班、能不能远程、有没有担保（担保另有问法，见下）。

## 7. 三个必答的现实问题

### 签证
`【只有你能填：你现在持什么签证、工作权限到什么时候、是否需要担保】`
**答的规矩**：一句话说清楚，**不主动展开、不流露焦虑**。
澳洲雇主问这个是流程需要，不是刁难。含糊其辞才会让他们警觉。
如果需要担保，正确的时机是**对方问起时**或者**流程推进到 offer 讨论时**，不是第一轮自己抛出来。

### 薪资期望
`【只有你能填：你的区间】`
**规矩**：给区间不给点值；先问对方这个岗位的 band（"这个岗位你们的预算区间是多少？"）；
如果必须先说，给一个你调研过的市场区间，并加一句"这个我可以按整体 package 谈"。
**不要**说"我对薪资没有要求"。

### 到岗时间
`【只有你能填】` 有具体日期就说具体日期。"随时"听起来像很急，"两周"是最安全的默认答案。

## 8. 红线 —— 一句都不要说

- **不要说这两个教学项目（concept-tracker / job-tracker）是工作经历。** 它们是自建的学习项目，主动说明。
- **不要说自己会 Jest / Vitest 写过多少测试**——两个商业仓里没有测试文件，这是查得到的。技能栏留着可以，讲成"我写过很多测试"不行。
- **不要给 Beyz 编量化数字。** 那段能报的只有 250ms 切片、60 秒 key TTL、utterance_end 2000ms、历史窗口 4 条，其余都没有 benchmark 撑。
- **不要评价前雇主的人。**
- **不要在没被问的时候主动交代弱点**——诚实不等于自我拆台。被问到才说，说完给改进动作。
- **听不懂就问。** 澳洲面试里 "Could you clarify what you mean by X?" 是加分的，硬答跑偏才是减分。

## 9. 面试前 30 分钟扫这一页

- 30 秒自我介绍，中英各一遍（出声）
- 时间线四个坑的答案，各一句
- "为什么转 AI" 三步，各一句
- 从素材库挑 4 条今天要用的，确认不重复
- 反问挑 3 条，写在纸上
- 签证 / 薪资 / 到岗，各一句
