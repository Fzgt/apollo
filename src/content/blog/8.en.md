---
title: Higher-Order Components in Depth
---

### How I think about it

- An HOC is like passing a component through a piece of middleware: it takes a component, gives it something extra, and returns a new one.
- That "something extra" can be data or UI.
  - For authorisation or data fetching, the parent does the work and passes the result down as props.
  - For error handling or extending the UI, the extra comes from wrapping more UI around the component on the way out.

```js
function withExtraProp(Component) {
    return function(props) {
        return <Component extraProp="someValue" {...props} />;
 };
}}, []);
```

### Details that matter

- **An HOC does not modify the original component.**
  - It is a pure functional wrapper: it creates a new component (usually called the wrapper) and leaves the original alone.
  - This is the important rule. Mutating the original component's prototype would destroy its reusability.
- **Naming**
  - HOCs are named `withSomething` (`withExtraProp`), so you can tell what it is at a glance.
  - You call it as `const EnhancedComponent = withSomething(MyComponent)`.
- **Static methods get lost**
  - If the original component has statics (`defaultProps`, `fetchData`), wrapping drops them by default. Use `hoist-non-react-statics` to copy them across.
- **Since React 18, HOCs are mostly for class components**
  - In function components, most HOC use cases are better served by a custom hook — shorter, and no extra layer in the tree.
  - Hooks have also filled out since React 18: `useSyncExternalStore`, `useId`, automatic batching, and so on.
  - A custom hook is excellent at sharing logic and data, but it cannot extend the UI.

### Where you use them

- **Authorisation and permissions.** Some components should only be reachable by authenticated users. Write an HOC that takes a component and returns a new one that checks authentication before rendering.
- **Data fetching.** The other common case. An HOC takes a component and returns one that fetches on mount and passes the data down as props.
- **Error handling.** An HOC that wraps the original component's render and shows an error message or fallback when something throws.
- **Purely extending the UI** — adding a layer around it.

### HOC vs custom hook

| | Higher-order component | Custom hook |
|---|---|---|
| **Shape** | Takes a component → returns a new component | A `useXxx` function |
| **Used for** | Sharing logic in class components, permissions, injecting data, wrapping UI | Sharing logic in function components, data fetching, state |
| **Upsides** | - Works on class components<br>- Can change both UI and data | - Shorter, no extra nesting<br>- Better type inference |
| **Downsides** | - Adds nesting (wrapper hell)<br>- Statics can be lost | - Cannot be used in class components<br>- Weak at extending UI |
| **Cost** | One more component render | Essentially none |
| **Statics** | Need `hoist-non-react-statics` | Not an issue |
| **React 18 guidance** | For class components, or when you need to wrap UI | The default way to share logic between function components |
| **Call site** | `withAuth(MyComponent)` | `const { data } = useAuth()` |

### In short

- **Class component** ➜ use an HOC.
- **Function component** ➜ custom hook when you are only sharing logic and data; HOC when you also need to wrap the markup.
- **Both** ➜ an HOC can call a custom hook, but only inside the function component it returns.

```javascript
 function withAuth(Component) {
  // ❌ you cannot call useAuth() here
  return function Wrapper(props) {
    // ✅ but you can call hooks here
    const { user } = useAuth();

    if (!user) return <LoginPage />;
    return <Component {...props} user={user} />;
  };
}
```

### What that mixed case tells you about hooks and HOCs

- A custom hook cannot wrap UI, because **a hook is just a function: it returns data or methods**, and **it cannot return new JSX wrapped around your component**.
- The rules of hooks: **hooks may only be called inside a function component or another custom hook**, never in an ordinary function or a class component.
- An HOC is itself an ordinary function, so a hook cannot go at its top level. But what an HOC returns *is* a function component, so hooks are fine inside that.
