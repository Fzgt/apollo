# ④ 脚本化接缝与 461 个测试

> **简历原句**
>
> **Put a scripted seam behind every external dependency** — the model provider, search, **httpx** page fetch and the clock — so the whole system runs with **no API keys and no network**: **461 pytest tests, 1.5 seconds end to end**.
>
> ---
>
> 在每个外部依赖背后都留了一道可脚本化的接缝 —— 模型服务、搜索、httpx 页面抓取和时钟 —— 所以整个系统不用 API key、不联网也能跑：461 个 pytest 测试，全程 1.5 秒。

2026-08-27 在本机复测过：跑测试的输出是 **461 passed、3 skipped、1.37s**，只收集不执行时是 **464 条**。简历写 461 指的是**通过数**，不含 3 条跳过；1.5 秒是**含收集用例在内的整轮墙钟时间，串行单进程**。

## 先把词说清

**seam（接缝）**：术语出自《修改代码的艺术》。**指你能在不修改这个位置的代码的前提下，改变程序行为的地方。**

**stub / fake / mock**：**stub** 返回写死的值；**fake** 是一个能用的简化实现（假时钟就是 fake）；**mock** 还会断言「你调了我几次」。**被问到能分清是加分项。**

**flaky test（不稳定测试）**：同样的代码有时红有时绿。**AI 系统的默认状态。**

**dependency injection（依赖注入）**：把依赖从外面传进来，而不是在内部自己 new 一个。

**ABC（Abstract Base Class，抽象基类）**：Python 里必须显式继承的接口，**可以带共享实现**。

**Protocol（结构化类型 / structural typing）**：Python 的「鸭子类型接口」——**不需要继承，长得像就算是**。

**transport layer（传输层）**：HTTP 客户端里**真正把字节送上网络的那一层**。

**process boundary（进程边界）**：字节离开这个进程的那个位置。**这条 bullet 的核心判据就落在这个词上。**

## 这条要讲清什么

**这是 Periplus 几条里证据最硬的一条：代码在本机，面试官当场就能自己跑。**

但**数字只是表皮**。它真正在讲的是**一个 AI 系统怎么做到没有 API key、没有网络也能全量测试**——而答案的核心是**接缝要放在最接近进程边界的位置**。

## 要解决什么

**AI 系统的测试有个根本困难：它依赖的东西全都是不确定的。**

模型同样的输入两次调用结果可能不同，服务商还会悄悄换模型版本。搜索今天和明天不一样。网页随时改版、随时失效。**时间每次都不同——而这个系统的过期判定直接吃时间。**

直接对着真实依赖写测试，结果是**测试随机变红（flaky）**；跑一次几十秒到几分钟；**每跑一次都花钱**；CI 里没网就全挂。

于是大多数 AI 项目的选择是**干脆不写测试，或者只留几个冒烟测试装装样子**。**这条 bullet 说的是另一条路：把不确定性全部关进四个可替换的口子里。**

## 接缝放在哪一层，决定了测试还剩多少真实性

**这一节是整条 bullet 的技术核心，答出来就赢了。**

那个脚本化的模型客户端**只覆写了一个方法**：把请求记下来，返回排好的回复。**别的什么都没动。**

**而基类还在真实运行的部分包括**：提示词组装、从模型返回里提取 JSON、用 Pydantic 校验格式、**校验失败之后的修复重试循环**、把每次调用记成一条审计记录并算 token 成本。

**这些全部还在跑，被换掉的只有「把请求发出去」那一下。**

**对比一下常见的错误做法**：在 agent 层替换整个对象，让它返回一份假的结果。**那样测试测的是「我的假对象返回了我塞进去的东西」，一行真实逻辑都没覆盖到。**

**判断标准一句话：接缝要放在最接近进程边界的位置，越靠外，被测的真实代码越多。**

这也是为什么评测那个模块的注释说：**只替换会离开进程的那两个，所以一个用例跑的是真实的编排器、agent、关卡和预算记账。**

## 四个接缝用了三种不同的注入手法

**能讲出为什么这三个地方用了不同手法，是深度的体现。**

**① 抽象基类 + 只覆写一个方法**——用在**模型和搜索**上。适用于**有大量真实的公共逻辑要保留**的场景：基类把所有共享行为实现掉，子类只填「怎么把字节送出去」。

**② Protocol（结构化类型）**——用在**时钟**上：

```python
class Clock(Protocol):
    def now(self) -> datetime: ...
    def monotonic(self) -> float: ...

class SystemClock:      # ← 注意：没有继承 Clock
    def now(self): return datetime.now(UTC)
    def monotonic(self): return time.monotonic()

class FakeClock:        # ← 也没有继承，只是「长得像」
    def advance(self, seconds: float) -> None:
        if seconds < 0:
            raise ValueError("a clock cannot go backwards")   # ← 业务不变量写进了行为
        self._now += timedelta(seconds=seconds)
        self._monotonic += seconds
```

**为什么这里不用抽象基类**：因为**接口只有两个方法、没有任何共享实现**，强制继承只是徒增耦合。**判据是：接口窄、无共享逻辑就用 Protocol；接口宽、有共享逻辑就用 ABC。**

**③ 换掉传输层**——用在**抓网页**上，**这个最妙**。换掉的**不是「抓网页」这个函数**，是 **httpx 的 transport 层**。

于是抓网页模块里那一整套逻辑**全部真实执行**：**robots 规则的解析与遵守、每个域名只允许一个请求在飞、同一域名连续请求之间的延迟、流式读取加字节上限、重定向跟随、缓存优先于网络。**只有最后建立网络连接那一步没发生。

**这就是接缝放得够外的价值：如果替换的是「抓网页」这个函数，上面这六条一条都测不到。**

另外还有第五个接缝，是**用哈希技巧做的确定性向量**。

## 为什么连时钟都要注入

时钟模块的文件头说得很直白：

```python
"""An injectable clock.

Nothing in the orchestrator calls ``datetime.now`` or ``time.monotonic`` directly.
Everything — wall-clock budgets, run/stage timestamps, and Auditor's freshness
``as_of`` date — goes through a Clock, so a test can move time forward by hand
instead of sleeping for real, and a replay stays deterministic.
"""
```

时间在这个系统里有三个用途：**运行时长预算、各种时间戳，以及判断证据新不新鲜的「今天」**。

**第三个才是关键。**这个系统的核心业务逻辑之一就是「这条证据过期了没有」，公式是**今天 − 页面发布日期，再和这类声明的新鲜度窗口比**。**所以时间本身就是业务输入，不是环境噪音。**

**不注入时钟会有两个后果。**

**第一是时间炸弹测试（time-bomb test）**：写一个测「三十天内的价格应该判有效」的用例，**过几个月它会自己变红**，这是最恶心的一类随机失败。

**第二是测试跑不快**：测超时和预算的用例得**真的 sleep**，一个一秒超时的用例就要等一秒——**四百多个测试跑一秒半这件事，本身就依赖假时钟**。

**假时钟把「等三十秒」变成一次赋值。**注意 `advance` 拒绝负数，抛的是 **"a clock cannot go backwards"**——**时钟不能倒流是个业务不变量，写在了行为里。**

## 461 这个数怎么核

只收集不执行的时候是 **464 条**，分布在 **17 个测试文件**里。最多的是**编排器和检索**这两块，各九十多和六十多，**加起来占了三分之一**——这两块正好是系统里最复杂、最容易出错的地方。**分布本身就是信息。**

**口径要主动说清，这是这条 bullet 上最容易被问穿的一点**：简历上的 **461 是通过数，不是收集数；收集是 464，差的 3 条是跳过的**。跳过的一直是同一批——**数据库重连测试，跳过条件是需要一个可连接的 PostgreSQL**。

**用通过数这个口径更好答**：461 就是真正跑过并且绿了的，**没有「收集了但没执行」的空隙**。但仍要能主动说清套件一共 464 条，**另外 3 条是有条件跳过（conditionally skipped）的数据库重连测试，不是失败**。**答不清这一点，会显得数字是拍的。**

**顺带说一句测试的构成**：这不是严格的单元/集成分层，**更像是按模块的行为测试**，每个用例都跑真实的类和真实的控制流，只有出进程的那一下被换成脚本。**被问「你们测试怎么分层的」，答这个比硬套测试金字塔诚实。**

## end to end 指什么，先定掉这个歧义

**正确的读法是「整个测试套件从头跑到尾约一秒半」。**从语法看它跟在「461 个 pytest 测试」后面，修饰的是那四百多个测试。

**但这个词在工程语境里通常指「端到端流程」**，很容易被听成「一次六阶段流水线跑完约一秒」。面试官如果按后一种理解，会问「**一秒就跑完六个阶段？那模型调用呢？**」——**你得能立刻分辨他问的是哪个。**

**想更清楚可以把简历里的 `end to end` 换成 `in`**：461 pytest tests **in** 1.5 seconds，歧义就没了。

## 这个时间数字的四个口径

**什么命令。** 进到 `server/` 跑 `pytest`，项目配置里已经设好了默认参数，**不用带任何选项**。

**串行还是并行。** **串行，单进程。**证据是开发依赖里只有 pytest、`pytest-asyncio` 和格式检查工具，**没有装 `pytest-xdist`**。**这一点反而是加分的**：一秒半是单进程串行跑完四百多个用例，**不是靠开八个进程堆出来的**；**没有并行还这么快，说明快的原因是没有 IO 等待，不是有并发。**

**含不含收集用例的时间。** pytest 自己报的 1.5 秒**含收集 + 执行**，**不含** Python 解释器启动、模块导入和包管理器开销。用 `time` 包住整条命令量到的是**两秒出头**，含全部。**简历印的是 pytest 自己报的那个数**，被问到时要能说清报的是哪个。**推荐报 pytest 那个，因为它是可比的**：换台机器包管理器的启动开销不一样，但套件本身的执行时间可比。

**哪台机器。** 一台 16GB 内存的 MacBook Pro。**并且要主动补一句：这个数字对机器不敏感**，因为它是纯 CPU 计算、**没有任何 IO 等待**，换台机器可能变成 0.9 秒或者 2 秒，**但不会变成 30 秒**。

**这个「不敏感」本身就是论点**——如果套件里还残留任何一个真实网络调用，机器和网络环境一变，**时间会跳一个数量级**；稳定在秒级，**说明 IO 真的清干净了**。

## 为什么能这么快

**逐条拆开，每一条都对应前面的一个接缝：**

- **省掉了网络往返**——靠假的 HTTP transport；没有它，每次抓页几百毫秒，**几十个页面就是十几秒**。
- **省掉了真实等待**——靠假时钟；抓取模块里每个域名之间要等一秒，**超时用例更是要等满**。
- **省掉了模型调用**——靠脚本化的模型客户端；一次模型调用几秒起，**这一项就能把套件拖到分钟级**。
- **省掉了向量模型加载**——靠哈希技巧做的假向量；**加载一个真的向量模型权重要几秒到几十秒**。
- **省掉了数据库往返**——靠那 3 个用例被跳过。

**最后那个假向量特别值得注意**：它用「把词哈希到固定的桶里再归一化」的办法造出确定性向量，**整个测试过程根本不导入那个重量级的向量模型库**。**这不只是快，也让测试不依赖模型权重文件的存在。**

## 这个数字真正的意义

**它不是在说「我们测试跑得快」，而是在说「我们的依赖隔离是完整的」。**

理由很简单：**这四类 IO，只要漏掉任何一个，时间就会立刻跳一个数量级。**漏一个网络调用是几秒到几十秒，漏一个真实等待是按秒累加，漏一个模型调用是分钟级。

**所以一秒半是个证明，不是个成绩。它证明的是没有任何一条测试路径偷偷溜出了进程。**

## 唯一一个能被当场验证的数字

其他数字要么在公司内网、要么需要特定环境、要么是别人系统里的口径。**这一条不一样**：面试官克隆仓库、装依赖、跑一条命令，**一秒多就能自己看到结果，不需要 API key，不需要网络**。

**主动提出这一点，效果比数字本身大得多**：这个仓库是公开的，进 `server/` 跑 `pytest` 就行，不需要任何 key 也不需要联网，**您现在就能验证**。

**一个能被当场验证的数字，会让面试官对你其他所有数字的信任度一起上升。**

## 英文怎么说

**三处最容易说错的。** **stub / fake / mock 三个词有别**（见开头）。**核心判据一句话**是 **the seam goes as close to the process boundary as possible — the further out it is, the more real code the test still exercises**。「一秒是证据不是成绩」说 **the second is evidence that no test path leaks out of the process, not a performance claim**。

**术语对照**：接缝 seam ／ 替换点 substitution point ／ 进程边界 process boundary ／ 不稳定测试 flaky test ／ 确定性 determinism ／ 假时钟 fake clock ／ 时间炸弹测试 time-bomb test ／ 依赖注入 dependency injection ／ 抽象基类 abstract base class ／ 结构化类型 structural typing ／ 传输层 transport layer ／ 重定向跟随 redirect following ／ 收集到 collected（对 passed）／ 有条件跳过 conditionally skipped ／ 串行/并行 serial / parallel。

## 30 秒回答

> AI 系统最难测的是它依赖的东西全是不确定的：模型两次调用结果不同，搜索和网页天天变，时间每次都不一样。所以我在每一个「字节要离开进程」的位置放了一道接缝——模型、搜索、抓网页、时钟——生产接真货，测试接脚本。关键是接缝放的位置：脚本化的模型客户端只覆写了「发请求」那一个方法，提示词组装、JSON 提取、schema 校验、修复重试、成本记账全都还在真实运行；抓网页换的是 httpx 的 transport 层，所以 robots 遵守、并发限制、重定向跟随这些逻辑全都真测了。判据是接缝要放在最接近进程边界的位置，越靠外被测的真实代码越多。结果是四百多个测试一秒半跑完，不用 key、不用网络。而这一秒半是个证据不是成绩：这四类 IO 漏掉任何一个，时间都会跳一个数量级。
