## One complete update, the fuller version

0. An update is triggered: `setState` is called
   → the reconciler assigns a lane (`requestUpdateLane`)
   → decide: sync or async?

```
┌─ sync lane: call performSyncWorkOnRoot directly, skip the scheduler, run to completion
│
└─ async lane:
   ① Scheduling:
      the taskQueue/timerQueue machinery decides when the render phase is allowed to start
      (nothing to do with lanes — the reconciler computes the lane and translates it into a
       priority number before handing it to the scheduler)

   ② The render phase (= reconciliation; the same thing):
      beginWork (run the component body, run the hooks, diff — same-level comparison plus key
      matching, apply tags)
      + completeWork (roll the tags back up)
      all of it in memory, invisible to the user, and interruptible

   ③ The commit phase:
      before mutation (getSnapshotBeforeUpdate)
      → mutation (the real DOM operations) → the current pointer switches
      → layout (componentDidMount / componentDidUpdate, useLayoutEffect)
      → passive (useEffect, asynchronous)
```

---

## ⚠️ The link people get wrong: going through the Scheduler ≠ being time-sliced

Between ① and ② above sits ①.5, and it is not optional. `DefaultLane` — an ordinary `setState` inside `setTimeout` or `.then()` — is an **async lane and does queue in the Scheduler**, but it is on the `includesBlockingLane` list, so `shouldTimeSlice` evaluates to `false` and the work ends up in `workLoopSync`: **rendered in one go, never yielding partway**. `setState` from a click or a keystroke is `SyncLane`: it takes the sync-lane branch in the diagram above, is flushed in a microtask, and never enters the Scheduler.

The lanes that actually take the concurrent loop and actually get time-sliced are `TransitionLane` (`startTransition` / `useDeferredValue`, plus what Next.js App Router and React Router wrap their navigations in) and `RetryLane` (a Suspense re-render).

For the source references, the full lane list, starvation protection and the "concurrent rendering ≠ time slicing" split, see #23; for telling the two identically-named `workLoop`s apart, see #22.
