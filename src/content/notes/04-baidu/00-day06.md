**七个核心点：**

| # | 要点 |
|---|---|
| 1 | 提交类操作要的是 **leading edge + 请求锁**，不是 debounce——「最后一次才生效」会让用户觉得没反应然后点更多次 |
| 2 | 按参数去重的锁复用同一个 Promise，**这个模式叫 Promise 去重，React Query / SWR 内部就这么做** |
| 3 | ⭐ **幂等 key 提前生成 + 存 sessionStorage**——刷新后还是同一个 key，否则刷新重试在后端看来是新的一笔 |
| 4 | ⭐ **默认失败，只有明确成功才展示成功**：显示失败用户会重试（有幂等兜底），显示成功但没到账会炸锅——**两种错法代价不对称** |
| 5 | ⭐ **前端减少无效负载，后端提供正确性**——这句话把提现那条 bullet 的分工讲干净了 |
| 6 | **loader 是文件级转换器，plugin 是构建级扩展点** |
| 7 | Webpack 5 两个关键变化：**filesystem cache**（构建提速主因）、**Node polyfill 移除**（体积下降主因，同时是不兼容一大类） |

第 1–5 点见[提现](/docs?section=baidu&item=d6-withdraw)，第 6–7 点见[Webpack](/docs?section=baidu&item=d6-webpack)。
