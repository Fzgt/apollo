# 那个被删掉的性能指标

> ⚪ **速查**。**这条声明已经从简历里删掉了**，换成了可证的 `detail pages open instantly, with no request at all`。
>
> **但下面这套分析仍然要会** —— 面试官问「你凭什么说详情页快」时，讲的就是它。

## 一、原来那句话是什么，为什么删

**原句**：`route preloading and hover prefetch: detail-page LCP under 500 ms`

**两处都有问题，所以两处都删了：**

| 短语 | 问题 |
|---|---|
| `route preloading`（路由级预加载） | ⚠️ **参照实现里指不到代码** —— 只做了 hover 预取，路由级的那套只存在于一份文档字符串里 |
| `detail-page LCP under 500 ms` | ⚠️ **这个指标在 SPA 里根本不成立**，而且代码里没有任何测量埋点 |

**现在的写法 `detail pages open instantly, with no request at all` 好在哪**：`with no request at all`（一个请求都不发）**是可以指着代码证明的事实** —— 预取把数据放进了缓存，详情页用同一把钥匙直接命中。**一句能证明的话，替掉了两句证不了的。**

## 二、⭐ 为什么 LCP 在这里不成立（这是最值钱的一段）

### 先说清 LCP 是什么

**LCP（Largest Contentful Paint，最大内容绘制）** 是谷歌定义的一个网页性能指标：**从页面开始加载，到「视口内最大的那块内容」渲染完成，用了多久。**

「最大的内容」通常是首屏的大图、视频封面，或者一大块正文文字。

**官方阈值**（取所有页面加载的 75 分位）：

| 评级 | LCP |
|---|---|
| 好 | ≤ 2.5 秒 |
| 需要改进 | 2.5 – 4.0 秒 |
| 差 | > 4.0 秒 |

**所以 500 毫秒是「非常快」** —— 只有及格线的五分之一。**但正因为它好看，被追问的概率也高。**

### ⚠️ 硬伤：LCP 是按「页面导航」算的

**关键在于：LCP 的计时起点是「浏览器开始加载一个页面」。**

而这个网站是 **SPA（单页应用）** —— **点一个链接跳到详情页，浏览器并没有重新加载页面**，只是 JavaScript 换掉了屏幕上显示的组件。**这种叫「软导航」（soft navigation），标准的 LCP 测量不会为它产生新的数值。**

（Chrome 有个实验性的软导航 API 能做这件事，但那不是默认行为，Lighthouse 和常用的测量库默认也不按它报。）

**于是就出现一个矛盾：**

| 进详情页的方式 | 有没有 LCP | hover 预取有没有用 |
|---|---|---|
| **直接输网址 / 从外部链接进来**（真·页面加载） | ✅ 有 | ❌ **没用** —— 用户根本没经过列表页 |
| **从列表页点进去**（软导航） | ❌ **标准口径下不产生新的 LCP** | ✅ **有用** |

> ⭐ **hover 预取优化的，恰恰是那条不产生 LCP 的路径。**
>
> 所以原来那句话要么测的是真页面加载（那预取没帮上忙，快是别的原因），**要么测的其实不是标准 LCP**（可能是自己用计时 API 量的组件渲染耗时，被叫成了 LCP）。

**这不代表那条 bullet 是假的** —— 数据预取确实让详情页秒开，**用户体感是真的**。**问题出在把这个体感套用了「LCP」这个有严格定义的指标名。**

## 三、如果被问「你怎么测的」

**假设简历上还留着这个数字，五个审计问题一个都答不上：**

| 问 | 要答什么 |
|---|---|
| **用什么工具测的** | **实验室数据**（Lighthouse、开发者工具的性能面板）还是**真实用户数据**（`web-vitals` 库上报、CrUX）？**这个区分是核心** |
| **什么环境** | Lighthouse 默认对移动端做 4 倍 CPU 降速 + 慢速 4G 模拟。**同一个页面移动端和桌面端能差三倍**，只说「500 毫秒」不说档位等于没说 |
| **样本多少** | 实验室数据单次波动很大，**至少跑 5 次取中位数**；真实用户数据要看 **75 分位**（这是官方口径，不是平均值） |
| ⭐ **优化前是多少** | **这条最重要** —— 没有基线，这个数字就只是「这个页面本来就快」，**跟你的架构一点关系都没有** |
| 实验室还是真实用户 | 同第一条 |
