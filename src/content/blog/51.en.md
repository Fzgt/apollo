title: for await...of and Async Iteration

> Everything that unfolded out of one line of streaming code: `for await (const text of textStream) stream.update(text);`

---

## 1. What it solves

A synchronous `for...of` walks arrays, Sets, Maps — **synchronous iterables** — and gets the next value immediately.

Streaming data does not work that way. A model generates token by token, the network arrives in chunks, a file is read block by block: **the next value has to be waited for.** `for await...of` (ES2018) exists for exactly that. Each round awaits the next value, runs the body when it arrives, and goes back to waiting.

```js
for await (const chunk of stream) {
  console.log(chunk);
}
```

---

## 2. What the sugar unfolds into

```js
// the sugar
for await (const text of textStream) {
  stream.update(text);
}

// the equivalent by hand
const it = textStream[Symbol.asyncIterator]();
try {
  while (true) {
    const { value, done } = await it.next();   // wait for the next chunk
    if (done) break;
    stream.update(value);
  }
} finally {
  await it.return?.();                          // clean up on early exit
}
```

The point: `for await...of` handles the `done` check and the cleanup on early exit for you.

---

## 3. The async iteration protocol

Any object that implements `Symbol.asyncIterator` — returning an object with a `next()` that returns a promise — can be walked by `for await...of`.

**By hand:**

```js
const ticker = {
  [Symbol.asyncIterator]() {
    let i = 0;
    return {
      async next() {
        if (i >= 3) return { done: true, value: undefined };
        await new Promise(r => setTimeout(r, 1000));
        return { done: false, value: i++ };
      },
    };
  },
};

for await (const n of ticker) console.log(n);  // 0, 1, 2 — one per second
```

**Async generators (the common way):**

```js
async function* fetchPages(urls) {
  for (const url of urls) {
    const res = await fetch(url);
    yield await res.json();       // each yield runs the loop body once
  }
}

for await (const page of fetchPages(urls)) {
  process(page);
}
```

`async function*` implements `Symbol.asyncIterator` for you and is the least effort way to produce an async sequence.

## 4. Two constraints you have to know

### 1. It has to be inside an async function

```js
// ❌ SyntaxError
function main() {
  for await (const x of stream) {}
}

// ✅
async function main() {
  for await (const x of stream) {}
}
```

Top-level await is supported in ES modules, so at module scope you can write it directly.

### 2. The loop is serial

Each round waits for the previous body to finish before fetching the next value. **There is no concurrency.**

```js
// serial: total time = the sum of them all
for await (const url of urls) {
  await fetch(url);        // one after another
}
```

If you want concurrency, do not use `for await`:

```js
// concurrent: total time = the slowest one
await Promise.all(urls.map(url => fetch(url)));
```

For streaming data, serial is **correct** — the order means something. But if you are just iterating a pile of independent tasks, `for await` slows you down for nothing.

## 5. Errors and early exit

**`try`/`catch` works normally**, and errors thrown inside the stream are caught here:

```js
try {
  for await (const chunk of stream) {
    process(chunk);
  }
} catch (err) {
  // the stream failed midway, the network dropped, and so on
  console.error('stream failed:', err);
}
```

**`break` triggers cleanup.** On an early exit, JavaScript calls the iterator's `return()` method, giving the stream a chance to release resources — close the connection, cancel the request. This is the part a hand-written `while` loop usually forgets.

```js
for await (const chunk of stream) {
  if (shouldStop) break;      // the underlying stream gets a return() call
  process(chunk);
}
```

## 6. Dropping the braces

```js
for await (const text of textStream) stream.update(text);
```

When the body of a `for`, `if`, or `while` is a **single statement**, the braces are optional and the behaviour is identical.

Compact, but most style guides discourage it — forgetting to add the braces when a second line appears is a classic bug:

```js
if (x) doA();
      doB();     // looks like it is inside the if; actually always runs
```

## 7. Where it actually shows up

```js
// streaming generation with the AI SDK
for await (const delta of textStream) ui.append(delta);

// a Node readable stream (native since Node 10)
for await (const chunk of fs.createReadStream('big.log')) {
  parse(chunk);
}

// a fetch response body (web streams)
const reader = res.body.pipeThrough(new TextDecoderStream());
for await (const chunk of reader) {
  console.log(chunk);
}

// read a huge file line by line without blowing up memory
const rl = readline.createInterface({ input: stream });
for await (const line of rl) {
  handle(line);
}
```

That last one is especially useful: **iterating a very large file line by line keeps memory constant**, unlike `readFileSync`, which loads the lot at once.

## 8. The trap everyone hits: incremental or cumulative

Streaming APIs emit one of two things, and **mixing them up guarantees a bug**:

| Semantics | What each message contains | What the front end does |
|---|---|---|
| **delta (incremental)** | Only the newly added fragment | Append: `text += delta` |
| **cumulative** | Everything so far | Replace: `text = full` |

The classic mismatch:

```js
// textStream emits deltas, but update() replaces
for await (const text of textStream) stream.update(text);
// → the user only ever sees the latest fragment, and the text flickers
```

The correct version depends on both sides:

```js
// a delta stream plus a replacing update → accumulate yourself
let acc = '';
for await (const delta of textStream) {
  acc += delta;
  stream.update(acc);
}
```

The other way round — a cumulative stream with an appending front end — gives you text repeating itself endlessly.

> The same trap appears in real-time speech recognition. Deepgram's `interim_results` is a **complete fresh guess at the current utterance** (cumulative) and must replace what is there; the `is_final` fragments can be accumulated. Get it wrong and the screen fills with duplicated text.
>
> **The first thing to establish when wiring up a streaming API is whether it emits deltas or cumulative content.** If the docs do not say, log the first three chunks and look.

## Quick reference

| Situation | Use |
|---|---|
| Iterating an array, Set, or Map | `for...of` |
| Iterating a stream or chunked data | `for await...of` |
| A batch of independent async tasks, concurrently | `Promise.all` |
| Producing an async sequence | `async function*` |
| Cleaning up on early exit | `break` (calls `return()` for you) |
| Catching errors from inside the stream | `try`/`catch` around the whole loop |
