# ④ 脚本化接缝与 461 个测试

> **简历原句**
>
> **Put a scripted seam behind every external dependency** — the model provider, search, **httpx** page fetch and the clock — so the whole system runs with **no API keys and no network**: **461 pytest tests, 1.5 seconds end to end**.
>
> ---
>
> 在每个外部依赖背后都留了一道可脚本化的接缝 —— 模型服务、搜索、httpx 页面抓取和时钟 —— 所以整个系统不用 API key、不联网也能跑：461 个 pytest 测试，全程 1.5 秒。

> ✅ **2026-08-27 在本机复测**：`uv run pytest` 输出 `461 passed, 3 skipped in 1.37s`，`--collect-only` 收集到 464 条。简历写 461 指的是**通过数**，不含 3 条 skip；1.5 秒是含 collection 的整轮墙钟时间，串行单进程。

## 这条 bullet 在讲什么

⭐ **这是三条里证据最硬的一条** —— 代码在本机，能指行号，**面试官当场就能自己跑**。

**但数字只是表皮。它真正在讲的是：一个 AI 系统怎么做到「没有 API key、没有网络也能全量测试」** —— 而答案的核心是第三节那一句：**接缝要放在最接近进程边界的位置。**

## 一、要解决什么

**AI 系统的测试有个根本困难：它依赖的东西全都是不确定的。**

| 依赖 | 为什么没法直接测 |
|---|---|
| **模型** | 同样的输入两次调用结果可能不同；服务商还会悄悄换模型版本 |
| **搜索** | 今天搜出来的和明天搜出来的不一样 |
| **网页** | 随时改版、随时 404 |
| **时间** | `now()` 每次都不同 —— **而这个系统的过期判定直接吃时间** |

**直接对着真实依赖写测试，结果是**：测试**随机变红**（这种叫 **flaky test**，不稳定测试）、跑一次要几十秒到几分钟、**每跑一次都花钱**、CI 里没网就全挂。

> **于是大多数 AI 项目的选择是：干脆不写测试，或者只留几个冒烟测试装装样子。**
>
> **这条 bullet 说的是另一条路 —— 把不确定性全部关进四个可替换的口子里。**

## 二、什么是 seam（接缝）

**术语出处**：Michael Feathers 的《修改代码的艺术》。

> **seam（接缝）= 你能在不修改这个位置的代码的前提下，改变程序行为的地方。**

**做法：在每一个「字节要离开进程」的位置放一个 seam** —— **生产环境接真货，测试环境接脚本。**

**四个 seam，正是简历列的那四个：**

| 依赖 | 生产实现 | 测试实现 | 注入手法 |
|---|---|---|---|
| **模型** | 真的调 API | `ScriptedClient` | 抽象基类，**只覆写一个方法** |
| **搜索** | 真的调搜索服务 | `ScriptedSearch` | 抽象基类 |
| **抓网页** | 真的发 HTTP | **假的传输层** | **换掉 HTTP 客户端的底层传输** |
| **时钟** | 真的读系统时间 | `FakeClock` | **结构化类型** |

（还有第五个：`ScriptedEmbeddings`，用哈希技巧做的确定性向量。）

## 三、⭐ 最关键的一点：seam 放在哪一层，决定了测试还剩多少真实性

**这一节是整条 bullet 的技术核心，答出来就赢了。**

看那个脚本化的模型客户端（`llm/scripted.py`）：

```python
class ScriptedClient(LLMClient):
    """按顺序返回排好的回复。"""
    async def _chat(self, messages, policy, *, json_object) -> RawResponse:
        self.requests.append(list(messages))     # 记下它被问了什么
        ...
        return RawResponse(text=reply, ...)      # 返回排好的回复
```

> ⭐ **它只覆写了 `_chat` 一个方法，别的什么都没动。**

**而基类负责这些**（`llm/base.py` 文件头注释直接写明了）：

- 提示词组装
- 从模型返回里**提取 JSON**
- **用数据模型校验格式**
- 校验失败后的**修复重试循环**
- 把每次调用记成一条审计记录、算 token 成本

> ⭐ **这些全部还在真实运行。被换掉的只有「把请求发出去」那一下。**

**对比一下常见的错误做法：**

```python
# ❌ 在 agent 层替换
mock_research_agent.run.return_value = fake_claims
```

**这样测试测的是「我的假对象返回了我塞进去的东西」—— 一行真实逻辑都没覆盖到。**

> ⭐ **判断标准一句话：seam 要放在最接近进程边界的位置。越靠外，被测的真实代码越多。**
>
> 这也是为什么评测那个模块的注释说 *"Only the two seams that leave the process are replaced, so a case exercises the real orchestrator, agents, gates and budget accounting"*（**只替换会离开进程的那两个**，所以一个用例跑的是真实的编排器、agent、关卡和预算记账）。

## 四、四个 seam 用了三种不同的注入手法

**能讲出「为什么这三个地方用了不同手法」，是深度的体现。**

### 手法 1：抽象基类 + 只覆写一个方法（模型、搜索）

**适用于「有大量真实的公共逻辑要保留」的场景。** 基类把所有共享行为实现掉，子类只填「怎么把字节送出去」。

### 手法 2：结构化类型（时钟）

```python
# orchestrator/clock.py:16-19
class Clock(Protocol):
    def now(self) -> datetime: ...
    def monotonic(self) -> float: ...
```

**`Protocol` 是 Python 的「结构化类型」（structural typing）** —— 它不要求你继承它，**只要你有这两个方法，你就算是一个 Clock**。

> **真实时钟和假时钟都没有继承 `Clock`。它们只是「长得像」就能用。**
>
> **为什么这里用 Protocol 而不是抽象基类**：因为接口只有两个方法、**没有任何共享实现**，强制继承只是徒增耦合。
>
> ⭐ **判据：接口窄、无共享逻辑 → 用 Protocol；接口宽、有共享逻辑 → 用抽象基类。**

### 手法 3：换掉传输层（抓网页）—— 这个最妙

```python
# tests/test_retrieval.py:63
httpx.AsyncClient(transport=httpx.MockTransport(handler), follow_redirects=True)
```

**换掉的不是「抓网页」这个函数，是 HTTP 客户端的传输层** —— 也就是「真正把字节送上网络」的那一层。

**于是抓网页模块里那一整套逻辑全部真实执行：**

- robots.txt 解析与遵守
- 每个域名只允许一个请求在飞
- 同一域名连续请求之间的延迟
- 流式读取 + 2MB 字节上限
- ⭐ **重定向跟随**（连这个行为都在真测）
- 缓存优先于网络

**只有最后建立网络连接那一步没发生。**

> ⭐ **这就是「seam 放得够外」的价值**：如果替换的是「抓网页」这个函数，上面这六条**一条都测不到**。

## 五、⭐ 为什么连时钟都要注入（高频追问）

`clock.py` 的文件头说得很直白：

> *"Nothing in the orchestrator calls `datetime.now` or `time.monotonic` directly."*
>
> （编排器里**没有任何地方直接读系统时间**。）

**时间在这个系统里有三个用途：**

1. **运行时长预算** —— 一次 run 最多能跑多久
2. **各种时间戳**
3. ⭐ **判断证据新不新鲜的「今天」**

**第三个才是关键**：这个系统的核心业务逻辑之一就是「**这条证据过期了没有**」，公式是 `今天 − 页面发布日期 > 该类声明的新鲜度窗口`。

> ⭐ **时间本身就是业务输入，不是环境噪音。**

**不注入时钟会怎样：**

| 问题 | 说明 |
|---|---|
| **时间炸弹测试** | 写一个测「30 天内的价格应该判有效」的用例 —— **过几个月它会自己变红**。这是最恶心的一类随机失败 |
| **测试跑不快** | 测超时和预算的用例得**真的 sleep**。一个 1 秒超时的用例就要等 1 秒 —— ⭐ **461 个测试跑 1.5 秒这件事，本身就依赖假时钟** |

**假时钟把「等 30 秒」变成一次赋值：**

```python
# clock.py:45-49
def advance(self, seconds: float) -> None:
    if seconds < 0:
        raise ValueError("a clock cannot go backwards")   # ⭐ 时钟不能倒流
    self._now += timedelta(seconds=seconds)
    self._monotonic += seconds
```

> **注意它拒绝负数** —— **时钟不能倒流是个业务不变量**，写在了行为里。

**一句话答法**

> 「因为**时间不是环境噪音，是业务输入**。这个系统要判断一条证据新不新鲜，判定依据就是当前时间减去页面发布时间。时钟不注入的话，**一是测试会变成时间炸弹** —— 今天绿的用例过几个月自己红；**二是测超时和预算就得真 sleep，整个套件跑不到一秒。**」

**分布本身就是信息**：编排器 67 个、检索 66 个，占了三分之一 —— **这两块正好是系统里最复杂、最容易出错的地方**（阶段编排与关卡、抓取与去重）。

## 八、先定掉一个歧义：`end to end` 指什么

| 读法 | 指什么 |
|---|---|
| ✅ **A** | **整个测试套件**从头跑到尾约一秒 |
| ❌ **B** | 一次六阶段流水线**跑完**约一秒 |

**正确的是 A。** 从语法看它跟在 `461 pytest tests` 后面，修饰的是那 461 个测试。

> ⚠️ **但 `end to end`（端到端）这个词在工程语境里通常指「端到端流程」，很容易被听成 B。** 面试官如果按 B 理解，会问「一秒就跑完六个阶段？那模型调用呢？」—— **你得能立刻分辨他问的是哪个。**
>
> **想更清楚可以改成 `461 pytest tests in 1.5 seconds`** —— 把 `end to end` 换成 `in`，歧义就没了。

## 十、这个时间数字的四个口径

### ① 什么命令

`cd server && uv run pytest`。项目配置里已经设好了默认参数，不用带任何选项。

### ② 串行还是并行

**串行，单进程。**

**证据**：开发依赖里只有 `pytest`、`pytest-asyncio`（异步测试支持）和 `ruff`，**没有装 `pytest-xdist`**（那是并行插件）。

> ⭐ **这一点反而是加分的**：**1.52 秒是单进程串行跑完 461 个用例，不是靠开 8 个进程堆出来的。**
>
> **没有并行还这么快，说明快的原因是「没有 IO 等待」，不是「有并发」。**

### ③ 含不含收集用例的时间

**这是两个数字的差别所在：**

| 数字 | 含什么 | 不含什么 |
|---|---|---|
| **1.52s**（pytest 自己报的） | **含**收集用例 + 执行 | 不含 Python 解释器启动、模块导入、`uv` 自身开销 |
| **2.02s**（`time` 量的） | 含**全部** —— 从敲回车到回到提示符 | — |

> **简历印的「1.5 seconds」就是 pytest 自己报的那个数**，不是 `time` 量的 2.02 秒。**被问到时要能说清报的是哪个。**
>
> **推荐报 pytest 自己那个 1.52 秒**，因为它是**可比的** —— 换台机器 `uv` 的启动开销不一样，但套件本身的执行时间可比。

### ④ 哪台机器

这台 MacBook Pro（16 GB 内存）。

**并且要主动补一句**：这个数字**对机器不敏感** —— 因为它是**纯 CPU 计算、没有任何 IO 等待**。换台机器可能变成 0.9 秒或 2 秒，**但不会变成 30 秒**。

> ⭐ **这个「不敏感」本身就是论点**：如果套件里还残留任何一个真实网络调用，**机器和网络环境一变，时间会跳一个数量级**。**稳定在秒级，说明 IO 真的清干净了。**

## 十一、为什么能这么快

**逐条拆开，每一条都对应 上半篇 里的一个 seam：**

| 省掉了什么 | 靠哪个 seam | 如果没有会慢多少 |
|---|---|---|
| **网络往返** | 假的 HTTP 传输层 | 每次抓页几百毫秒，几十个页面就是十几秒 |
| **真实等待** | 假时钟 | 抓取模块里每个域名之间要等 1 秒，**光这一项就够喝一壶**；超时用例更是要等满 |
| **模型调用** | 脚本化的模型客户端 | 一次模型调用几秒起 —— ⭐ **这一项就能把套件拖到分钟级** |
| **向量模型加载** | 哈希技巧做的假向量 | 加载一个真的向量模型权重要几秒到几十秒 |
| **数据库往返** | 3 个用例被跳过 | 连接 + 建表 + 清理 |

> **最后那个假向量特别值得注意**：它用「**把词哈希到固定的桶里再归一化**」造出确定性向量，**整个测试过程根本不导入那个重量级的向量模型库**。**这不只是快，也让测试不依赖模型权重文件的存在。**

## 十二、⭐ 这个数字真正的意义

**它不是在说「我们测试跑得快」，而是在说「我们的依赖隔离是完整的」。**

**理由很简单：这四类 IO，只要漏掉任何一个，时间就会立刻跳一个数量级。**

- 漏一个网络调用 → 几秒到几十秒
- 漏一个真实等待 → 按秒累加
- 漏一个模型调用 → 分钟级

> ⭐ **所以「一秒」是个证明，不是个成绩。它证明的是：没有任何一条测试路径偷偷溜出了进程。**
>
> **这是把 上半篇 和这一条串成一个论点的方式**：**前半篇说结构（四个 seam），这半篇说这个结构真的没漏。**

## 十三、⭐ 唯一一个能被当场验证的数字

**其他数字要么在公司内网、要么需要特定环境、要么是别人系统里的口径。**

**这一条不一样：面试官 clone 仓库、装依赖、跑一条命令，一秒后就能自己看到结果。不需要 API key，不需要网络。**

**主动提出这一点，效果比数字本身大得多：**

> 「这个仓库是公开的，`cd server && python -m pytest` 就能跑，**不需要任何 key 也不需要联网 —— 您现在就能验证。**」

> ⭐ **一个能被当场验证的数字，会让面试官对你其他所有数字的信任度一起上升。**

## 十四、本篇术语英文对照

| 中文 | 英文 |
|---|---|
| 接缝 | **seam**（*a scripted seam behind every external dependency*） |
| 替换点 | **substitution point** |
| 进程边界 | **process boundary**（⭐ *put the seam as close to the process boundary as possible*） |
| 打桩 / 假实现 | **stub · fake · mock**（三者有别，见下） |
| 不稳定测试 | **flaky test** |
| 确定性 | **determinism** |
| 假时钟 | **fake clock** |
| 时间炸弹测试 | **time-bomb test** |
| 注入 | **inject · dependency injection** |
| 抽象基类 | **abstract base class** |
| 结构化类型 | **structural typing**（Python `Protocol`） |
| 传输层 | **transport layer** |
| 重定向跟随 | **redirect following** |
| 速率限制 | **rate limiting** |
| 收集到的用例 ↔ 实际执行 | **collected ↔ executed**（464 collected, 461 passed, 3 skipped） |
| 有条件跳过 | **conditionally skipped** |
| 串行 ↔ 并行 | **serial ↔ parallel**（`pytest-xdist`） |
| 端到端 | **end to end**（⚠️ 这里指整个套件，不是一次流水线） |

> ⭐ **三个最容易说错的**：
>
> 1. **stub / fake / mock 的区别**：stub 返回写死的值；**fake 是个能用的简化实现**（假时钟就是 fake）；mock 还会断言「你调了我几次」。被问到能分清是加分项
> 2. 核心判据一句话：**"The seam goes as close to the process boundary as possible — the further out it is, the more real code the test still exercises."**
> 3. 「一秒是证据不是成绩」说 **the second is evidence that no test path leaks out of the process, not a performance claim**
