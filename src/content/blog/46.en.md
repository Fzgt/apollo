# LangChain vs LangGraph

## 1. What each one is

| | LangChain | LangGraph |
|---|---|---|
| Role | A high-level framework for building LLM applications quickly | A low-level execution engine for orchestrating stateful, controllable agents |
| Analogy | Prefabricated parts plus assembly instructions | The engine underneath, controlling state flow and execution |
| Relationship | LangChain's `create_agent` now runs on the LangGraph engine | It is LangChain's execution runtime, and it can be used on its own |

They are not competitors, and they are not two arrangements of the same layer. They are **stacked**: LangChain is the developer experience layer, LangGraph is the execution engine.

---

## 2. The core difference is not just "linear vs branching"

A common misreading is that LangChain handles linear flows and LangGraph handles branching ones. That is the surface. The real differences:

### 1. State management

- **LangChain (LCEL / chains)**: data is passed along in order, state is implicit, and nothing persists across steps.
- **LangGraph (StateGraph)**: there is one explicit state object spanning the whole graph, and every node reads and writes that shared state.

### 2. Granularity and control of the execution model

- LangChain wraps the intermediate steps — especially the classic `AgentExecutor` — into a black box. Fast to build with, low control.
- LangGraph exposes what happened at each step, where the state is, and whether it can pause, for you to control precisely.

### 3. Runtime capabilities unique to LangGraph — not a side effect of "being a graph"

These exist even when the graph degenerates into a straight line, because they are runtime mechanisms rather than a matter of topology:

- **Durable execution**: resume from a breakpoint, recover after a crash
- **Checkpointing**: every step's state can be saved, and you can rewind to any point in history
- **Human in the loop**: pause at a node and wait for approval before continuing
- **Multi-agent collaboration and parallel scheduling**: dependencies and parallelism between tasks can be declared explicitly

---

## 3. Can they be used separately

- **LangGraph works without LangChain's high-level API**: install only the `langgraph` package, skip its model integrations and chains, wire up the model API yourself (call the OpenAI or Anthropic SDK directly), and build a StateGraph agent. It is not dependency-free at the package level, though — `langgraph` hard-depends on `langchain-core` (it is in the PyPI metadata), which is where the base classes in the next point come from.
- **But there is ecosystem gravity**: LangGraph's core concepts (`BaseChatModel`, `BaseTool`, `Runnable`, `RunnableConfig`) come largely from the LangChain ecosystem, and its idioms seep into node logic. Separating completely is not effortless.
- **Basic LangChain does not require LangGraph**: in the docs' own words, "You do not need to know LangGraph for basic LangChain agent usage."

---

## 4. When to use which

### LangChain

- You want a working LLM application from nothing, fast
- You want ready-made model integrations and tool wrappers (600+ integrations)
- The task is a relatively simple linear flow (standard RAG: retrieve → assemble the prompt → generate)
- You do not need fine control over intermediate state or execution order

### LangGraph

- The flow has conditions and loops (generate code → test → retry on failure)
- Multi-agent systems, passing tasks and results between roles
- Critical operations needing human approval (pause before sending an email or deleting a file)
- Long-running tasks that may be interrupted and resumed (the "leave and come back" case)
- Fine control over parallelism and dependencies between tasks

---

## 5. Migration path

If the project uses the old `AgentExecutor` (in maintenance mode; the docs recommend migrating soon):

```
AgentExecutor → create_agent (LangChain 1.0, the simplest; already runs on LangGraph internally)
             → a full StateGraph (if you need node-level control)
```

---

## 6. In one sentence

> **LangChain** answers "how do I get an LLM into my application quickly, with less glue code".
> **LangGraph** answers "in a complex agent system, how does state flow, how is it persisted, can it pause and resume, and can several agents work together".
>
> LangChain is enough for simple tasks. The moment you need loops, branches, multiple agents, human intervention, or resumption from a breakpoint, LangGraph is the answer.
