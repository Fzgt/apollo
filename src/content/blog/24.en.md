# Notes on useLayoutEffect

## What it is, in one sentence

**`useLayoutEffect` is the last chance to change the DOM before the page is painted.**

## Where it sits in the pipeline

```
render phase (the diff is done; what changes is locked in)
        ↓
commitBeforeMutationEffects
    getSnapshotBeforeUpdate runs — it can read the old DOM, not change it
        ↓
commitMutationEffects
    the real DOM is mutated; React has done its DOM work
    the current pointer switches
        ↓
commitLayoutEffects (the layout phase)
    ★ useLayoutEffect runs here ★
    at this moment: the DOM is updated, but the browser has not painted yet
        ↓
    [the browser paints]
        ↓
useEffect runs — the user has already seen the frame
```

## Why it is synchronous

It **blocks painting**. The browser waits for it to finish before drawing this update to the screen.

That blocking is exactly what makes it useful: you can measure the DOM inside it and adjust the layout by hand, and the user never sees the "before" frame, because the browser has not drawn anything yet.

Compare `useEffect`: it does not block at all. It is scheduled asynchronously after the commit is finished, by which point the frame is already on screen.

## The common question: "does changing the DOM in here re-run the diff?"

It depends on what you do:

- **Touching the real DOM directly (a ref plus native APIs)**: no diff, nothing to do with the reconciler. It is the same as changing the page with jQuery or plain JavaScript.
- **Calling `setState` inside it**: that triggers a **completely new, independent** update (diff plus commit). React guarantees the new pass finishes before the browser paints — so several small cycles may run back to back underneath, but the user only ever sees the final version, never anything half-finished.

## Compared with getSnapshotBeforeUpdate

The two sit at two different moments in the DOM's lifecycle:

| | getSnapshotBeforeUpdate | useLayoutEffect |
|---|---|---|
| When | **Before** the DOM changes | **After** the DOM changes, **before** it is painted |
| What you can do | Read only — writing is pointless, the new DOM overwrites it immediately | Write, and the user sees no seam |
| In a sentence | A last look at the old DOM before it dies | The new DOM is born but not yet visible — reshape it while you can |
